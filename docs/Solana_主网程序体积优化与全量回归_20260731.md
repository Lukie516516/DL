# Solana 主网程序体积优化与全量回归

更新时间：2026-07-31

## 1. 结论

本轮只优化 Solana 生产程序的构建产物和验证工具，没有修改任何 Rust 业务源码、指令、账户布局、PDA seed、Program ID 或权限规则。

最终候选产物：

- 24 个生产程序二进制总大小从 `8,633,576` bytes 降到 `7,870,608` bytes。
- 减少 `762,968` bytes，约 `8.84%`。
- 23 个程序采用逐程序 `--optimize-size` 产物。
- `deal_dex_quoter` 在 `--optimize-size` 下反而从 `142,264` 增长到 `157,736` bytes，因此保留默认构建产物。
- 候选产物已在全新隔离 Localnet 真实部署并跑完生产拓扑、资产、国库、DEX、域名、排行、治理和程序升级闭环。

> 本轮未向 Solana Mainnet 发送任何交易，也未使用主网 SOL。

## 2. 为什么没有直接合并或删减程序

大幅减少 24 个程序的数量需要合并程序、重排账户或改变 CPI/权限边界，这会改变现有安全架构和业务实现。本轮按“业务逻辑不变”的约束，只使用编译器尺寸优化，不做架构重构。

尝试裁剪 `anchor-spl` feature 后，二进制大小没有收益，反而增加依赖维护风险，因此已完整撤回，未保留该改动。

## 3. 构建安全修复

发现 `cargo build-sbf --workspace --optimize-size` 会受 Cargo feature 合并影响，为某些依赖程序产生约 `896` bytes、ELF entry point 为 `0` 的 `no-entrypoint` stub。该文件不是可部署的 Solana 程序。

新增的 `solana/sdk/build-production-programs.mjs` 采用以下策略：

1. 只处理明确的 24 个生产程序。
2. 每个程序分别独立构建默认版和 `--optimize-size` 版。
3. 校验程序 keypair 权限、Program ID、IDL address、SBF ELF machine 和非零 entry point。
4. 丢弃无效产物，只选择更小的有效产物。
5. 生成包含每个 `.so` 与 IDL SHA-256 的构建报告。

可复现命令：

```bash
cd solana/sdk
npm run build:production:optimized
```

## 4. ABI 和业务不变证据

- Rust 业务源码 hash 在构建前后不变：`sourceChanged = false`。
- 28 份 Anchor IDL 与冻结基线逐字节一致。
- `instructionAbiChanged = false`。
- `accountLayoutChanged = false`。
- 24 个 Program ID 与对应 keypair 全部一致。
- 24 个候选 `.so` 在隔离 Localnet 部署后从链上 dump，24/24 SHA-256 与本地正式产物一致。
- `--optimize-size` 可能改变计算单元消耗，因此不只做 ABI 检查，还用真实优化字节码执行了完整运行时和 Localnet 交易回归，未出现计算上限或行为差异。

## 5. 隔离 Localnet 全链路结果

本轮使用新账本、新状态目录和独立 RPC，没有复用旧的 Localnet 状态：

- 24/24 优化程序真实部署成功。
- 24/24 链上 dump hash 一致。
- 生产拓扑初始化成功，20 个业务 authority 交给 Governance Executor PDA，former admin 越权被拒绝。
- Core 普通 Open、指定地址和 OpenTokenToken Fast 流程通过，错误顺序、超时边界、重复加入等反向分支被拒绝。
- DEX 初始化流动性、Stable → DC swap、滑点拒绝和 minter 撤销通过。
- 域名注册、冻结 NFT、metadata、resolve、转移、挂单、撤单、成交和国库收费通过。
- 域名大厅、黑名单、消息 DC 销毁、选人、Domain Entry、v0+ALT、排行质押与取回通过。
- 生产国库 controller 为 Governance Executor PDA 时，普通钱包直接从国库出款被拒绝；治理路径支付 SOL 和 DC 均成功，余额差值精确一致。向国库入金仍保持无需授权。
- Governance Executor 调用 Upgradeable Loader 升级 canary 成功，业务状态 hash 不变，buffer 关闭。24/24 Upgrade Authority 最终均为 Governance Executor PDA。

## 8. 本轮改动清单与业务影响

| 改动 | 目的 | 是否改变业务逻辑 |
|---|---|---|
| 新增逐程序优化构建器 | 降低 `.so` 大小并拒绝无效 stub | 否 |
| `sdk/package.json` 新增优化构建命令 | 提供可复现入口 | 否 |
| Localnet 脚本支持 `SOLANA_LOCAL_STATE_DIR`/`SOLANA_WALLET_PATH` | 使每次回归可用新账本和隔离状态 | 否，默认路径与原行为不变 |
| 新增生产治理国库测试 | 验证 controller 交给 PDA 后的 SOL/DC 出款 | 否，只是测试工具 |
| 修正 Mainnet genesis 常量与增加有限 RPC 重试 | 防止正确主网被误判，提高只读检查可诊断性 | 否，主网检查项没有减少 |

## 9. 尚未完成/不可误解的事项

- 没有完成外部独立安全审计；内部回归不等于第三方审计。
- 没有在 Solana Mainnet 部署、初始化或交权。
- 没有在公开网络上完成真实 ETH → Solana 跨链消息和 2/3 bridge 确认。
- 程序层优化已经完成，但若要继续大幅降低 SOL 预算，必须讨论合并程序/重构权限边界，这将不再是“业务不变”的无风险优化。

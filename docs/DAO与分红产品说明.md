# DAO 与分红体系产品说明

本文用于给产品、运营和管理层快速理解 DL 项目的 D 代币、DAO 治理、协议分红和 NFT 用户否决机制。

这份文档不展开合约实现细节，重点说明“这个体系解决什么问题、钱怎么分、谁能管、用户如何参与”。

---

## 1. 总体定位

DL 项目里会有两类核心资产：

| 资产 | 定位 | 主要作用 |
| --- | --- | --- |
| DL | 协议主代币 | 交易奖励、支付、燃烧、生态流通 |
| D | 协议分红权和治理席位 | 分协议收入、参与 DAO 否决治理 |

可以简单理解为：

```text
DL 是生态里的流通币。
D 是协议层的席位和分红权。
```

D 不设计成普通无限增发代币，而是固定总量、稀缺、偏协议权益属性。

---

## 2. D 代币规则

第一版 D 的核心规则：

| 项目 | 规则 |
| --- | --- |
| 总量 | 固定 100 D |
| 精度 | 8 位小数，类似 Bitcoin |
| 是否可转让 | 可以转让 |
| 是否可增发 | 不可增发 |
| 分红权 | 按持有比例分协议收入 |
| 席位门槛 | 持有 2.5 D 及以上，拥有 DAO 席位资格 |

```text
如果一个人持有 1 D，就拥有协议 1% 的分红权。
如果一个人持有 2.5 D 或更多，就成为一个治理席位，可以参与 DAO 否决。
```

D 部署时会一次性 mint 100 D 到指定地址，建议这个地址是多签或专门的分配钱包，而不是普通个人钱包。

## 3. 分红体系

### 3.1 分的是什么钱

分红只分协议收入。

协议收入主要来自：

| 来源 | 说明 |
| --- | --- |
| 交易手续费 | Deal 成交产生的协议手续费 |
| 域名收入    | 域名注册、市场、广告等收入 |
| 其他协议收入 | 后续新增模块产生的可分配收入 |

这些收入先进入 treasury。

### 3.2 为什么最终用 DL 分

treasury 可能收到很多种资产，例如 USDT、ETH、BNB、TRX 或其他币。

为了让分红口径统一，V1 建议：

```text
treasury 收到各种收入
可安全兑换的资产先换成 DL
再用 DL 进行分红
```

这样用户最终领取的是 DL，不需要每种杂币都单独领取。

### 3.3 分红流程

标准流程：

```text
1. 协议收入进入 treasury。
2. 运营 / DAO 把可兑换资产换成 DL。
3. treasury / dividendSource 把本轮 DL 授权给分红合约。
4. D 席位可以发起分红提案；无人否决后 executor / DAO 创建一轮分红。
5. 系统记录本轮快照。
6. D 持有人按快照时的持仓比例领取。
```

普通 D 持有人不能绕过 DAO 直接创建分红轮；但达到席位门槛的 D 持有人可以发起“协议分红提案”。提案无人否决并执行后，由 DAO/executor 触发分红轮，资金从 treasury/dividendSource 进入分红合约。

---

## 4. 分红快照机制

分红采用快照机制，防止重复领取。

人话解释：

```text
每次分红开始时，系统记录一个快照。
这一轮只认快照时谁持有 D、持有多少 D。
快照之后再转走 D，不影响这一轮分红。
快照之后买入 D，只能从下一轮开始参与分红。
```

例子：

```text
D 总量 = 100
本轮分红池 = 10,000 DL
A 在快照时持有 1 D

A 可领取 = 1 / 100 * 10,000 = 100 DL
```

如果 A 领取后把 D 转给 B，B 不能再领取这一轮，因为 B 在快照时没有这部分 D。

---

## 5. 杂币兑换 DL 的处理

treasury 可以收到很多币，但不是所有币都适合自动兑换。

V1 建议规则：

| 情况 | 处理方式 |
| --- | --- |
| 主流币，有流动性 | 可以换成 DL 进入分红 |
| 有明确兑换路径 | 可以按路径兑换 |
| 没有交易池 / 流动性差 | 暂时留在 treasury |
| 风险币 / 恶意币 | 不自动处理 |

不同链上的兑换方式不同：

| 链 | 常见兑换场所 |
| --- | --- |
| Ethereum | Uniswap |
| BSC / BNB Chain | PancakeSwap 或 Uniswap |
| TRON | SunSwap / SUN.io |

关键不是“接入某一个交易所”，而是每条链上要有 DL 的交易池。

例如要让 USDT 能换 DL，需要有：

```text
DL / USDT 池
```

如果某个杂币想换 DL，则需要有路径：

```text
杂币 -> USDT -> DL
```

没有路径的币，不建议强行换。

## 6. DAO 治理体系

DAO 的目标不是让所有人投赞成票，而是给核心权益人一个“否决权”。

V1 采用的是否决型治理：

```text
有人提出参数修改或重大变更。
在规定时间内，如果有席位反对，提案失败。
如果没人反对，到期后可以执行。
```

这种模式适合当前项目阶段，因为它比复杂投票更轻，执行效率更高。

---

## 7. 常规提案

常规提案主要处理日常运营参数。

常规提案可以理解为“日常运营旋钮”，包括但不限于：

| 类型 | 可治理内容 |
| --- | --- |
| 交易手续费 | 点对点交易手续费、非 DL 交易手续费、DL-DL 特殊费率 |
| LP / Swap 手续费 | 池子交易手续费、订单簿取消手续费、路由相关费率 |
| DL 奖励比例 | 成交后给 A/B/C 的 DL 奖励比例、手续费折算奖励比例 |
| 信用分参数 | 交易信用分基础倍率、信用差系数上下限、可记录信用的模板范围 |
| NFT 价格 | 官方 DealInfoNFT 铸造价格、图片/资料上限、赛季编号 |
| 消息费用 | 免费/付费消息开关、消息 burn 价格、消息长度限制 |
| 创建成本 | 创建 deal 是否 burn DL、burn 价格、哪些入口需要 burn |
| 时间参数 | deal 超时窗口、B 占坑可替换时间、创建/结束时间记录口径 |
| 交易白名单 | 官方认可币种、保证金币种、可用于报价的 token |
| 域名费用 | 域名注册价、域名市场手续费、域名广告费率、广告押金规则 |
| 域名治理 | 域名榜单上报者、黑名单相关运营参数、广告踢出时间 |
| 流动性参数 | Pair 手续费、虚拟流动性参数、是否允许创建新交易对 |
| 分红运营 | 分红周期、每轮分红额度、哪些 treasury 资产可兑换成 DL |
| 前端/索引体验 | 批量读取上限、分页上限、事件索引推荐字段 |
| 模块开关 | 消息模块、信用分记录、C 位奖励、OpenTokenToken 快速成交入口 |
| 轻权限白名单 | 允许第三方代创建 deal、允许特定模块上报/记录活动 |

常规提案不应该直接替换核心合约，也不应该迁移 treasury、mint 权限、owner 权限。这些属于重大提案。

建议流程：

```text
席位钱包发起提案
进入 48 小时否决窗口
任意 D 席位可以否决
无人否决则可以执行
```

这里的“席位”指持有 2.5 D 或以上的钱包。

---

## 8. 重大提案

重大提案影响更大，不应该只由 D 席位单层决定。

重大提案例子：

| 类型 | 例子 |
| --- | --- |
| 合约升级 |
| 权限迁移 | treasury、mint 权限、recorder 权限 |
| 分红规则重写 | 改变 D 分红逻辑 |
| 信用体系迁移 | 迁移信用分或更换 CreditGraph |

建议流程：

```text
席位钱包发起重大提案
进入更长的席位否决窗口
任意 D 席位可以否决
同时开放官方 NFT 用户否决
如果两边都没有达到否决条件，到期后执行
```

第一版默认重大提案窗口为 120 小时。

---

## 9. 官方 NFT 用户否决

为了避免 D 席位过度中心化，重大提案会接入官方 DealInfoNFT 的用户否决。

规则：

```text
只有官方 DealInfoNFT 参与。
外部 NFT 不参与治理。
一个有效官方 NFT 记一票。
达到有效 NFT 数量的 20% 否决，则重大提案失败。
```

这里的 20% 不是全部 NFT 总量，而是有效治理 NFT 的数量。

有效治理 NFT 需要近期有过真实行为，例如：

| 行为 | 是否记为活跃 |
| --- | --- |
| 成功完成 deal | 是 |
| 发起 deal | 是 |
| 领取分红 | 是 |
| 参与治理否决 | 是 |
| 单纯持有 NFT 但长期无行为 | 不一定有效 |

当前默认有效窗口为 90 天。

---

## 10. NFT 否决权快照

NFT 否决也采用快照逻辑，防止临时买卖刷票。

人话解释：

```text
提案创建时，谁持有这个官方 NFT，谁对这条提案有否决权。
提案创建后再把 NFT 转走，新买家不能投这条旧提案。
下一条新提案会重新按新的持有人快照计算。
```

这样可以避免有人在提案期间大量借入、买入、转移 NFT 来影响结果。

## 11. 整体流程示例

### 11.1 一次分红

```text
本月协议收入进入 treasury。
运营把其中可分配部分换成 50,000 DL。
D 席位发起分红提案；无人否决后，DAO / executor 创建一轮 50,000 DL 分红。
系统记录 D 持仓快照。
用户按自己快照时的 D 持仓比例领取。
```

如果某用户持有 3 D：

```text
3 / 100 * 50,000 = 1,500 DL
```

### 11.2 一次常规参数调整

```text
席位钱包提案：把某项手续费从 0.3% 调到 0.25%。
进入 48 小时窗口。
如果没有 D 席位否决，到期后执行。
如果任意 D 席位否决，提案失败。
```

### 11.3 一次重大升级

```text
席位钱包提案：替换核心交易模板。
进入 120 小时窗口。
D 席位可以否决。
官方有效 NFT 用户也可以否决。
如果 D 席位或 NFT 用户任何一边触发否决，提案失败。
如果都没有否决，到期后执行。
```

## 12. 当前已确定规则

| 项目 | 当前方案 |
| --- | --- |
| D 总量 | 100 |
| D 精度 | 8 位 |
| D 是否可转让 | 可以 |
| D 是否增发 | 不增发 |
| 席位门槛 | 2.5 D |
| 分红资产 | DL |
| 分红依据 | D 持仓快照 |
| 分红开轮执行权限 | 仅 executor / DAO 执行账户 |
| D 席位能否发起分红 | 可以发起分红提案；不能直接绕过 DAO 开轮 |
| DAO 类型 | 否决型治理 |
| 常规提案 | D 席位否决 |
| 重大提案 | D 席位否决 + 官方 NFT 用户否决 |
| NFT 投票权 | 按提案创建时持有人快照 |
| NFT 否决阈值 | 默认有效 NFT 的 20% |
| NFT 活跃窗口 | 默认 90 天 |
| 旧 Governor | 不作为新部署和前端主路径 |

## 13. 还需要确认的问题

| 问题 | 当前建议 |
| 没有交易对的币 | 先留 treasury，不自动换 |
| owner 权限归属 | 上线后转多签或治理 |
| NFT 活跃窗口是否固定 | 默认 90 天，可由治理调整 |
| NFT 否决阈值是否固定 | 默认 20%，可由治理调整 |

---

## 14. 一句话总结

```text
D 是固定 100 枚的协议席位和分红权；
协议收入最终换成 DL 分给 D 持有人；
分红按快照防止重复领取；
2.5 D 以上拥有 DAO 席位否决权；
常规参数由 D 席位否决；
重大变更还要接受官方 NFT 用户的第二重否决；
这套体系让协议收入、治理权和用户保护机制形成闭环。
```

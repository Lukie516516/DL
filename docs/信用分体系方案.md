# 信用分体系方案 V1

这份是可直接复制阅读版，去掉了代码块和 Markdown 表格，避免转发到群、飞书、Word 时出现 `text`、表格乱码或缩进异常。

## 一、方案一句话

信用绑定官方 DealInfoNFT，而不是钱包。

信用只来自成功完成的点对点 deal。低信用用户和高信用用户完成真实交易时，会获得更大的额外成长。每个 NFT 维护自己交易过对象的 top5 信用快照，交易时双方候选人 PK，最高者成为 C 位，并获得现有 DL 增发奖励。

## 二、核心定位

1. 信用体系只认官方 DealInfoNFT。
2. 信用跟 tokenId 走，可以随着 NFT 买卖转移。
3. 外部 NFT 可以做头像、名片、资产或门禁，但不接入信用体系。
4. V1 只有一个核心分数：信用分 creditScore。
5. 不单独做关系分。
6. 信用分不衰减，是长期资产。
7. 旧 totalDLMinted 不参与新信用。
8. 老 NFT 初始信用从 0 开始。

技术实现上，信用分不直接写在 DealInfoNFT 合约内部，而是写在独立的 DealCreditGraph 账本里：

DealCreditGraph.creditScore[tokenId]

产品含义上，它仍然是跟官方 NFT 走的。因为信用分用 tokenId 记账，谁持有这个官方 NFT，谁就拥有这个 tokenId 对应的信用资产。

## 三、信用分从哪里来

信用分唯一产出方式：成功完成点对点 deal。

也就是说，信用分不靠 burn、不靠发消息、不靠域名、不靠 mint、不靠 swap。只有真实完成的双方交易，才会产生信用分。

### 交易行为

成功完成 deal：

- 是否加信用：是，唯一来源。
- 计算口径：按本次真实手续费的 U 价值计算基础信用。

### 不产生信用的行为

以下行为都不产生信用分：

1. 手动 burn DL。
2. 发消息，无论免费还是付费。
3. 域名注册、域名广告、域名相关消耗。
4. 铸造 InfoNFT。
5. swap 交易或 swap fee burn。
6. 创建 deal 但未成功完成。
7. 失败交易或取消交易。

这些行为可以继续保留原本的业务功能，但不进入信用分体系。

创建 deal、免费消息、失败交易、取消交易：

- 是否加信用：否。
- V1 不加分，也暂时不扣分。

## 四、交易信用怎么计算

交易信用由两部分组成：

最终获得信用分 = 基础贡献分 + 额外奖励分

基础贡献分 = 本次手续费的 U 价值

额外奖励分 = 基础贡献分 × 信用差系数

信用差系数 = 对方信用分 ÷ 自己信用分

信用差系数有上下限：

- 最低：0.01
- 最高：2

所以完整表达是：

本次获得信用分 = 本次手续费 U 价值 + 本次手续费 U 价值 × 限制后的（对方信用分 ÷ 自己信用分）

这个设计的含义是：

1. 每笔成功交易都会根据真实手续费贡献给双方基础信用。
2. 低信用用户和高信用用户完成交易时，低信用用户获得更多额外成长。
3. 高信用用户和低信用用户交易时，额外奖励较少，但仍然能获得基础贡献分。

## 五、数字例子

假设：

- A 信用分：10000
- B 信用分：200
- 交易金额：10000U
- 手续费率：0.3%

本次手续费：

10000U × 0.3% = 30U

所以双方基础贡献分都是 30 分。

### A 是高分方

A 的额外奖励系数：

200 ÷ 10000 = 0.02

A 的额外奖励：

30 × 0.02 = 0.6

A 本次总获得：

30 + 0.6 = 30.6 信用分

### B 是低分方

B 的额外奖励系数：

10000 ÷ 200 = 50

但最高只能按 2 算。

B 的额外奖励：

30 × 2 = 60

B 本次总获得：

30 + 60 = 90 信用分

这个结果表达的是：

1. 高信用用户完成真实交易，至少能拿到基础贡献分。
2. 低信用用户如果能和高信用用户完成真实交易，会获得更大的信用成长。

## 六、0 分怎么处理

0 分就是 0 分，不设置初始保底分。

但计算额外奖励时，需要处理除零问题：

1. 自己信用 = 0，对方信用 = 0：额外奖励系数为 0。
2. 自己信用 = 0，对方信用 > 0：额外奖励系数为 2。
3. 自己信用 > 0，对方信用 = 0：额外奖励系数为 0。
4. 自己信用 > 0，对方信用 > 0：额外奖励系数 = 对方信用 ÷ 自己信用，并限制在 0.01 到 2 之间。

例子：

- A 信用：10000
- B 信用：0
- 基础贡献分：30

A 获得：

基础 30 + 额外 0 = 30

B 获得：

基础 30 + 额外 60 = 90

## 七、top5 信用快照

每个官方 NFT 会维护自己交易过对象中的 top5 信用快照。

这里记录的是：上次成功交易后，对方在我这里的信用快照。

规则：

1. 只有成功交易才会刷新 top5。
2. 对方在别处涨分，不会自动刷新到我的 top5。
3. 再次交易后，双方互相刷新对方的信用快照。
4. 每个 NFT 最多维护 5 个 top 信用对象。

这样可以避免一个高信用 NFT 自动进入所有人的信用网络。

## 八、C 位奖励怎么选

C 位可以理解为：本次交易双方信用网络里 PK 出来的最强信用人。

对 A 来说，候选人包括：

1. A 自己当前信用分。
2. A 的 top5 里信用快照最高的人。

对 B 来说，候选人包括：

1. B 自己当前信用分。
2. B 的 top5 里信用快照最高的人。

然后 A 侧最高者和 B 侧最高者 PK：

1. 谁分高，谁就是 C。
2. 平局没有 C。

C 位奖励 V1 先沿用当前机制：

1. 继续通过增发 DL 奖励。
2. 暂时不从真实手续费里切分。

也就是说，新信用体系第一版主要替换“C 是谁”，暂时不改变 C 奖励的来源和额度。

## 九、防刷规则

为了防止自己刷自己：

同一个 owner 持有的两个官方 NFT 互相交易时：

1. 不加信用。
2. 不刷新 top5。
3. 不产生 C 位。

没有官方 NFT 的用户仍然可以交易，但：

1. 不加信用。
2. 不进入 top5。
3. 不参与 C 位。

外部 NFT 不接信用体系，只能做展示、资产或门禁。

非交易行为不产生信用，避免通过 burn、消息、域名或 swap 低成本刷分。

## 十、已确认规则

1. 信用载体：只认官方 DealInfoNFT。
2. 信用存储：信用分存在独立 DealCreditGraph 里，但按官方 NFT tokenId 记账。
3. 外部 NFT：只做名片、资产、门禁，不接信用。
4. 信用是否可买卖：可以，信用跟 tokenId 走。
5. 核心分数：只有信用分，不做关系分。
6. 信用衰减：不衰减。
7. top5：每个 NFT 维护交易过对象的 top5 信用快照。
8. top5 刷新：只有再次成功交易才刷新。
9. 信用唯一产出方式：成功完成点对点 deal。
10. 交易信用口径：按 U 手续费价值计算。
11. 非交易行为：不产生信用。
12. swap：不产生信用。
13. C 位：双方本人和 top5 候选中最高者 PK。
14. 平局：不出 C。
15. 同 owner：不加信用、不刷新 top5、不出 C。
16. C 奖励：V1 继续用当前 DL 增发机制。
17. 老 totalDLMinted：不参与新信用。
18. 老 NFT 初始信用：从 0 开始。

## 十一、未来升级和迁移

信用分是长期资产，不能因为信用图合约升级或规则调整而丢失。

因此 V1 需要保留迁移能力：

1. 旧 DealCreditGraph 继续保存旧信用分和 top5 快照。
2. 如果未来必须部署新的 DealCreditGraph，可以把旧图里的 creditScore 和 top5 快照按 tokenId 导入新图。
3. 导入完成后，把 Factory 的 creditGraph 指向新图。
4. 新图导入完成后锁定迁移入口，防止后续随意改历史信用。

这样，官方 NFT 本身不需要换，tokenId 不需要换，用户持有的信用资产也不会因为重部署而消失。

## 十二、一句话总结

信用绑定官方 NFT，而不是钱包；信用可以随着 NFT 买卖转移；信用唯一来自成功完成的点对点 deal；交易基础信用按 U 手续费计算；低分和高分完成交易时，低分获得更多额外成长；每个 NFT 只记录交易过的 top5 信用快照；C 位就是双方信用网络里 PK 出来的最强信用人；第一版 C 位奖励继续沿用现有 DL 增发机制。

# Deal 协议 DAO 治理架构汇报

**文件版本**：2026-06-08  
**适用读者**：产品负责人、运营负责人、管理层

---

## 一、整体定位

Deal 协议的治理体系建立在三类资产的分工之上，每类资产有独立且不重叠的职责：

| 资产 | 定位 | 核心职责 |
|---|---|---|
| **DC（DealCoin）** | 协议流通代币 | 交易奖励、手续费、生态激励、可增发可销毁 |
| **D** | 协议权益代币 | 分红权、治理投票权、席位资格，**固定总量 100** |
| **DealInfoNFT** | 官方身份 NFT | 交易信用载体、重大治理第二院投票资格 |

三者关系简单来说：

> DC 管流通，D 管权益，NFT 管身份与重大决策的用户侧参与。

---

## 二、D 代币的核心规则

D 是整个协议的权益核心，规则极简且固定：

- **总量永远是 100 D**，不可增发，不可销毁
- **1 D = 1% 的主网分红权**，持多少分多少
- **持有 2.5 D 及以上**，即拥有 DAO 席位资格
- 席位的权利：可发起提案、拥有**一票否决权**
- D 可以自由转让，持仓变化实时影响后续分红和投票权

数字含义举例：

> 100 D 最多可以产生 40 个独立席位（100 ÷ 2.5 = 40）。  
> 若协议当期分红池为 100,000 DC，持有 5 D 的地址可领取 5,000 DC。

---

## 三、提案分层治理

所有治理行为分为三种类型，权限逐层递进：

### 3.1 参数调整提案（D-only）

**适用场景**：日常运营参数的调整，例如：
- 协议手续费、DC 奖励倍率
- 身份 NFT 铸造价格
- 域名注册费、市场手续费
- 交易时间窗口、安全边界参数
- 新增交易对、调整虚拟流动性

**通过规则**：
- 赞成票累计达到 **70 D** 即通过
- 任意席位（≥ 2.5 D）可在提案期内行使**一票否决**

**特点**：门槛清晰，方向稳定，适合频率较高的运营调节。

---

### 3.2 国库打款提案（D-only）

**适用场景**：向指定地址拨付协议资金，例如：
- 外部合作拨款
- 审计、法务、基础设施支出
- 运营支出

**提案必须写明**：打什么资产、打多少、打给谁、用途说明

**通过规则**：
- 赞成票累计达到 **70 D** 即通过
- **国库打款提案没有一票否决权**（防止少数席位阻断合理支出）

**特点**：去掉了一票否决，避免单一席位借助否决权对资金流向形成过强控制。

---

### 3.3 重大提案（D + 活跃 NFT 双院）

**适用场景**：影响协议根基的决策，例如：
- 核心合约升级或更换
- 治理规则本身的修改
- 分红规则修改
- D 代币规则变更
- 核心权限（owner、admin、minter）迁移

**通过规则**（双院同时达标才可执行）：

| 院 | 通过条件 |
|---|---|
| D 院 | 赞成 D ≥ 70 D |
| NFT 院 | 当前活跃 NFT 快照中，≥ 70% 赞成 |

同时：任意 D 席位可在提案期内行使**一票否决**。

**活跃 NFT 的定义**：官方 DealInfoNFT，且在过去 90 天内有治理活跃记录（参与投票、领取分红等）。快照在提案激活时锁定，防止临时增持操控。

**特点**：最高安全级别。协议的根本规则由 D 持有人和真实活跃用户共同把关，任何一方单独无法通过。

---

## 四、投票机制——质押即投票

区别于传统快照投票，本协议采用**物理质押模型**：

1. 支持者将 D 代币**转入治理合约**（物理转移，不是授权委托）
2. 质押额即等于赞成票数，实时累计
3. 提案结束后（无论通过、否决、取消），D **自动归还**原持有人，无需手动提取
4. 质押期间 D 不在钱包，但**仍计入分红快照**，质押者不损失分红权

**为什么这样设计**：
- 投票即锁仓，表达真实意愿，无法轻易一键撤回再影响市场
- 自动归还消除操作摩擦，用户体验更友好
- 分红补偿保证质押者不因参与治理而被惩罚

## 五、分红体系

### 分红资产

主网分红统一使用 **DC（DealCoin）**。

### 分红来源

协议在主网的可分配收入，经由 treasury / dividendSource 归集后，兑换为 DC 进行分配。

### 分红流程

```
协议收入进入主网 treasury
  ↓
可安全兑换的资产换成主网 DC
  ↓
D 席位发起分红提案（参数调整类）
  ↓
提案通过且未被席位否决
  ↓
执行账户开启本轮分红，锁定快照
  ↓
D 持有人按快照持仓比例领取 DC
```

### 分红计算

```
个人可领 = (个人持仓 D / 100) × 本轮分红池 DC
```

举例：本轮分红 10,000 DC，持有 3 D → 可领 300 DC。

**重要边界**：
- 分红和治理**仅在以太坊主链**，其他链的 Deal 协议正常运行但不承载 D 的分红与治理
- AUSD/USDT 的交易手续费进入 DC 交易对流动性池（非直接分红），通过市场机制反映 DC 价值
- DC 的 Swap 手续费直接销毁，deflation 为主

## 六、提案生命周期

```
任何人均可发起提案（无持仓门槛）
  ↓
提案进入 [待激活] 状态
  ↓
D 持有人质押支持，累计超过 2.5 D
  ↓
提案进入 [投票中] 状态
  ↓
┌─────────────────────────────┐
│  同期可随时发生：席位一票否决  │  → 提案立即终止，质押 D 自动归还
└─────────────────────────────┘
  ↓（未被否决）
赞成票（质押 D）累计达到 70 D
（重大提案额外需要 NFT 院 70% 赞成）
  ↓
提案进入 [可执行] 状态
  ↓
任意账户触发执行，链上动作生效
  ↓
所有质押 D 自动归还原持有人
```

## 七、安全设计亮点

| 设计 | 作用 |
|---|---|
| 一票否决仅限席位（≥ 2.5 D） | 防止零成本干扰，否决需真实利益绑定 |
| 国库提案无否决权 | 防止少数席位绑架合理支出 |
| 重大提案双院机制 | 协议核心修改需要 D 持有人与真实活跃用户双重背书 |
| NFT 活跃窗口（90 天） | 排除长期不活跃的 NFT，防止休眠账户被激活来操控投票 |
| 提案激活门槛（2.5 D） | 零成本提案需至少一名席位认可才可进入投票 |
| 质押自动归还 | 消除用户忘记取回 D 的风险 |
| 分红补偿质押期 | 质押参与治理的用户不损失分红权 |

## 九、一句话总结

> D 是协议的股权，持 1 D 得 1% 分红，持 2.5 D 拥有席位与否决权。  
> 日常参数由 D 多数决，国库出款由 D 决策且不设否决，协议根本变更须 D 与真实活跃用户双院通过。  
> 所有投票以质押为代价，提案结束后 D 自动归还，全程链上透明。

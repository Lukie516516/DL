# DAO 基本设定

> 说明：这份文档描述的是 **DAO 计划改造版口径**，用于产品、运营、前端和合约改造对齐，不等于当前链上已经全部生效的治理实现。

更细的参数项见 `docs/DAO可治理参数清单.md`。

---

## 1. 一句话版本

```text
DealCoin（DC）负责生态流通。
D 是协议权益、主网分红和主网治理代币。
D 固定总量 100，18 位精度，1 D = 1% 分红权。
持有 2.5 D 及以上拥有席位资格，并保留一票否决权。
参数调整和 treasury 指定打款只由 D 投票。
升级和重大提案由 D + 当前活跃官方 DealInfoNFT 双院通过。
D 发行、D 投票、D 分红都只在 ETH 主链进行。
```

---

## 2. 资产分工

| 资产 | 定位 | 主要作用 |
| --- | --- | --- |
| `DealCoin（DC）` | 协议主代币 | 交易奖励、支付、燃烧、生态流通 |
| `D` | 协议权益代币 | 主网分红权、主网治理投票权、席位资格、一票否决权 |
| `DealInfoNFT` | 官方身份 NFT | 信用载体、交易身份、重大提案第二院投票资格 |

核心关系：

```text
DC 负责生态流通。
D 负责主网协议权益。
DealInfoNFT 负责真实用户身份和重大治理中的用户侧参与。
```

---

## 3. 主链范围

这次治理改造的明确边界如下：

| 项目 | 规则 |
| --- | --- |
| D 代币发行 | 只在 ETH 主链 |
| D 投票 | 只在 ETH 主链 |
| D 分红 | 只在 ETH 主链 |
| 非主网 Deal | 可以正常运行 |
| 非主网 DC | 可以作为本链生态流通币 |
| 非主网 D 治理 / 分红 | 不开放 |

补充说明：

```text
其他链上的 Deal、域名、Swap 可以继续跑。
但其他链不承载 D 治理，也不承载 D 分红。
recognized 资产继续按当前逻辑进入 pair，不计入 treasury 分红来源。
```

---

## 4. D 代币规则

| 项目 | 计划规则 |
| --- | --- |
| 总量 | 固定 100 D |
| 精度 | 18 位 |
| 是否可转让 | 可以 |
| 是否可增发 | 不可增发 |
| 分红权 | `1 D = 1%` 分红权 |
| 席位门槛 | 持有 `2.5 D` 及以上 |
| 席位权利 | 可发起提案；保留一票否决权 |

人话解释：

```text
持有 1 D = 拥有协议 1% 的分红权。
持有 2.5 D 或以上 = 拥有 DAO 席位资格。
D 可以转让，但只影响未来分红和未来提案。
```

部署建议：

```text
100 D 在部署时一次性 mint 到指定主网地址。
这个地址建议是多签或专门的分配钱包，不建议是个人日常钱包。
```

## 5. 治理参与方

### 5.1 D 持有人

适用范围：

- 参数调整
- treasury 指定打款
- 升级 / 重大提案

计票方式：

```text
不再单独写 quorum。
直接按绝对赞成门槛判断。
D-only 提案通过条件 = 赞成票达到 70 D。
```

这代表：

- `不投票` 不等于反对
- 但 `不投票` 会让提案更难凑满 70 D 赞成

### 5.2 当前活跃官方 DealInfoNFT

只参与：

- 升级 / 重大提案

不参与：

- 普通参数调整
- treasury 指定打款
- 分红轮创建本身

计票方式：

```text
只认官方 DealInfoNFT。
1 个 tokenId = 1 票。
按提案创建时的快照计票。
重大提案通过条件 = 当前活跃 NFT 快照总票数中，70% 赞成。
```

### 5.3 当前活跃 NFT 的定义

计划沿用现有“活跃治理 NFT”模型：

```text
官方 DealInfoNFT
+ 在活跃窗口内有治理活跃记录
= 当前活跃 NFT
```

默认活跃窗口：

- `90 天`

活跃行为可以包括：

- 参与治理投票
- 参与重大提案 NFT 投票
- 领取主网分红
- 其他后续接入的治理活跃行为

> 现有代码里已经有 `DealNftGovernanceActivity` 和 `NftVetoRegistry` 这套“活跃 NFT 快照”基础设施；后续只是把它从“20% NFT 否决”改成“70% NFT 赞成通过”。

## 6. 提案分层

| 提案类型 | 参与方 | 通过条件 | 投票期 | 投票期内否决规则 |
| --- | --- | --- | --- | --- |
| 参数调整 | 只有 D | `赞成 D >= 70 D` | `48 小时` | 投票期内任意合格 D 席位可一票否决 |
| treasury 指定打款 | 只有 D | `赞成 D >= 70 D` | `120 小时` | 投票期内任意合格 D 席位可一票否决 |
| 升级 / 重大提案 | D + 当前活跃 NFT | `赞成 D >= 70 D` 且 `赞成 NFT >= 当前活跃 NFT 快照的 70%` | `120 小时` | 投票期内任意合格 D 席位可一票否决 |

## 7. D 席位一票否决

这是这次方案里保留的强保护机制。

规则：

```text
只要地址在否决快照时持有 >= 2.5 D，
它就保留一票否决权。
```

否决时间：

- 和对应提案的投票期一致
- 参数调整为 `48 小时`
- treasury 指定打款为 `120 小时`
- 升级 / 重大提案为 `120 小时`

适用范围：

- 参数调整
- treasury 指定打款
- 升级 / 重大提案

执行顺序建议：

```text
1. 提案进入投票期。
2. 投票期内，D 持有人可以投赞成。
3. 投票期内，任意合格 D 席位可以直接一票否决。
4. 一旦被否决，提案立即失败。
5. 投票期结束时，如果没有被否决，再检查是否达到通过条件。
6. 达到通过条件则通过；未达到则失败。
```

这代表治理会更保守。  
这是有意设计，不是副作用。

## 8. 分红体系

### 8.1 分红资产

主网分红统一使用：

- `DealCoin（DC）`

### 8.2 分红来源

来源可以是协议在主网 treasury / dividendSource 中可分配的资产。

建议流程：

```text
1. 协议收入进入主网 treasury / dividendSource。
2. 可安全兑换的资产换成主网 DC。
3. treasury / dividendSource 授权分红合约。
4. D 席位发起分红相关提案。
5. 提案投票通过且未被席位否决后，executor 创建分红轮。
6. D 持有人按主网 D 快照领取主网 DC。
```

补充边界：

```text
recognized 资产继续按当前逻辑进入 pair，不算 treasury 分红来源。
没有安全兑换路径的资产，先留在 treasury，不自动进入分红。
普通用户不能拿自己的钱伪装协议分红。
```

### 8.3 分红快照

```text
D 总量 = 100
本轮分红池 = 10,000 DC
A 在快照时持有 1 D

A 可领取 = 1 / 100 * 10,000 = 100 DC
```

## 9. 重大提案范围

以下事项建议统一归类为“升级 / 重大提案”：

- 核心合约升级
- 重新部署并接线新 Factory / Router / Reader / Treasury
- 治理规则修改
- 分红规则修改
- D 代币规则修改
- treasury 控制权迁移
- 核心权限迁移
- 信用体系迁移

简单说：

```text
改旋钮 = 参数调整
动国库 = D-only treasury 打款提案
换合约 / 换治理 / 换权益规则 = 重大提案
```

## 10. 典型流程

### 10.1 参数调整

```text
1. 席位地址发起参数调整提案。
2. D 持有人在 48 小时内投票。
3. 投票期内，任意合格 D 席位可以一票否决。
4. 如果被否决，提案立即失败。
5. 投票期结束时，如果赞成票达到 70 D 且未被否决，到期执行。
```

### 10.2 treasury 指定打款

```text
1. 席位地址发起打款提案。
2. 提案写清楚：打什么资产、打多少、打给谁、用途是什么。
3. D 持有人在 120 小时内投票。
4. 投票期内，任意合格 D 席位可以一票否决。
5. 投票期结束时，如果赞成票达到 70 D 且未被否决，执行 treasury 打款。
```

### 10.3 升级 / 重大提案

```text
1. 席位地址发起重大提案。
2. 提案写清楚：旧地址、新地址、变更原因、风险说明、审计情况。
3. D 持有人和当前活跃 NFT 在 120 小时内分别投票。
4. 只有 D 赞成票达到 70 D，且 NFT 赞成票达到当前活跃 NFT 快照的 70%，提案才算投票通过。
5. 投票期内，任意合格 D 席位可以一票否决。
6. 投票期结束时，如果双院达标且未被否决，到期执行升级。
```

## 11. 与现有代码的关系

### 11.1 可以复用的基础件

| 模块 | 合约 | 可复用原因 |
| --- | --- | --- |
| D 代币 | `contracts/D.sol` | 已是 100 D、18 位精度、2.5 D 席位门槛 |
| 主网分红 | `contracts/VoteDividendClaimer.sol` | 已支持 D 快照分红 |
| 官方 NFT | `contracts/DealInfoNFT.sol` | 已是官方身份 NFT 载体 |
| NFT 活跃记录 | `contracts/DealNftGovernanceActivity.sol` | 已支持活跃窗口、活跃供应量统计 |

### 11.2 需要改造或替换的治理件

| 当前合约 | 当前逻辑 | 计划改造方向 |
| --- | --- | --- |
| `DealSeatVetoGovernor.sol` | 否决制 | 改为投票制 + 投票期内席位一票否决 |
| `NftVetoRegistry.sol` | 活跃 NFT 20% 否决阈值 | 改为活跃 NFT 70% 赞成通过模型 |
| `DealDao.sol` | OZ Governor 试验路径 | 视最终方案决定是否复用或废弃 |

这部分要明确：

```text
当前代码里确实已经有“活跃 NFT 快照”这部分。
但它现在服务的是 NFT 否决，不是 NFT 赞成通过。
所以治理合约层仍需要改造。
```

## 13. 对外总结

```text
D 是 ETH 主链上的协议权益与治理代币，总量固定 100，18 位精度。
1 D = 1% 分红权，2.5 D 以上拥有席位资格和一票否决权。
参数调整和 treasury 指定打款只由 D 决定。
升级和重大提案由 D 与当前活跃官方 DealInfoNFT 双院通过。
所有提案在投票期内均可被合格 D 席位一票否决。
主网分红统一用 DC 发放，其他链不承载 D 分红和 D 治理。
```

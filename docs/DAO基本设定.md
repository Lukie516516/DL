# DAO 基本设定

这份文档是主文档，讲清楚“D 是什么、钱怎么分、谁能提案、谁能否决、代码由哪些合约承载”。更细的参数项见 `docs/DAO可治理参数清单.md`。

---

## 1. 一句话版本

```text
DealCoin（DC）是生态流通币和协议主代币。
D 是协议分红权和治理席位。
持有 D 可以按比例领取协议分红。
持有 2.5 D 以上成为 DAO 席位，可以发起和否决提案。
常规参数走 D 席位否决。
重大升级走 D 席位否决 + 官方 DealInfoNFT 用户否决。
```

---

## 2. 资产分工

| 资产 | 定位 | 主要作用 |
| --- | --- | --- |
| `DealCoin（DC）` | 协议主代币 | 交易奖励、支付、燃烧、生态流通 |
| `D` | 协议权益代币 | 协议分红权、DAO 席位资格、治理否决权 |
| `DealInfoNFT` | 官方身份 NFT | 信用、交易身份、重大提案用户否决 |

核心关系：

```text
DealCoin（DC）负责生态流通。
D 负责协议权益。
DealInfoNFT 负责真实用户身份和治理用户侧保护。
```

---

## 3. D 代币规则

| 项目 | V1 规则 |
| --- | --- |
| 总量 | 固定 100 D |
| 精度 | 8 位小数，类似 Bitcoin |
| 是否可转让 | 可以 |
| 是否可增发 | 不可增发 |
| 是否可销毁 | 当前不开放 burn |
| 分红权 | 按持有比例领取协议分红 |
| 席位门槛 | 持有 `2.5 D` 及以上 |
| 一人多地址识别 | V1 不做，链上直接按地址持仓判断 |

人话解释：

```text
持有 1 D = 拥有协议 1% 的分红权。
持有 2.5 D 或以上 = 拥有 DAO 席位资格。
D 可以转让，但转让只影响未来分红和未来提案。
```

部署时，100 D 会一次性 mint 给指定地址。这个地址建议是多签或专门的分配钱包，不建议是普通个人钱包。

## 4. 分红体系

### 4.1 分的是什么

分红只分协议收入。

协议收入主要包括：

| 来源 | 说明 |
| --- | --- |
| 交易手续费 | Deal 成交产生的协议手续费 |
| 域名收入 | 域名注册、域名市场、域名广告等收入 |
| 其他协议收入 | 后续新增模块产生的可分配收入 |

这些收入先进入 `treasury` 或指定的 `dividendSource`。

### 4.2 为什么最终用 DealCoin（DC）分

treasury 可能收到很多资产，例如 USDT、USDC、ETH、BNB、TRX 或其他 token。

V1 建议统一成：

```text
协议收入进入 treasury
可安全兑换的资产换成 DealCoin（DC）
再用 DealCoin（DC）给 D 持有人分红
```

这样用户最终领取的是 DealCoin（DC），不需要每种杂币都单独领取。

没有安全兑换路径、流动性太差、疑似垃圾币的资产，先留在 treasury，不自动进入分红。

### 4.3 标准分红流程

```text
1. 协议收入进入 treasury / dividendSource。
2. 运营、多签或 DAO 把可分红资产换成 DealCoin（DC）。
3. treasury / dividendSource 授权分红合约使用本轮 DealCoin（DC）。
4. D 席位发起分红提案。
5. 提案无人否决后，executor / DAO 执行账户创建分红轮。
6. 分红合约记录 D 持仓快照。
7. D 持有人按快照时的持仓比例领取 DealCoin（DC）。
```

重要规则：

```text
普通 D 持有人不能绕过 DAO 直接创建分红轮。
达到 2.5 D 的席位可以发起分红提案。
提案通过后，分红资金来自 treasury / dividendSource，不来自发起人的个人钱包。
```

## 5. 分红快照

分红使用快照机制，防止重复领取。

```text
每次分红开始时，系统记录一个快照。
这一轮只认快照时谁持有 D、持有多少 D。
快照之后再转走 D，不影响这一轮分红。
快照之后买入 D，只能从下一轮开始参与分红。
```

例子：

```text
D 总量 = 100
本轮分红池 = 10,000 DC
A 在快照时持有 1 D

A 可领取 = 1 / 100 * 10,000 = 100 DC
```

如果 A 领取后把 D 转给 B，B 不能再领取这一轮，因为 B 在快照时没有这部分 D。

## 6. DAO 治理模型

V1 采用“否决型治理”

```text
有人提出参数修改或重大变更。
进入否决窗口。
如果有合格席位否决，提案失败。
如果没人否决，到期后可以执行。
```

---

## 7. 常规提案

常规提案用于日常运营参数。

典型范围：

| 类型 | 可治理内容 |
| --- | --- |
| 交易手续费 | 点对点交易手续费、非 DC 交易手续费、DC-DC 特殊费率 |
| Swap 参数 | Pair 手续费、虚拟流动性、订单簿取消手续费 |
| 奖励参数 | DealCoin（DC）奖励比例、信用分基础倍率、信用差系数 |
| NFT 参数 | DealInfoNFT 铸造价格、图片/资料上限、赛季编号 |
| 消息费用 | 免费/付费消息开关、消息 burn 价格、消息长度限制 |
| Deal 时间 | timeout、B 占坑可替换时间、读接口分页上限 |
| 交易白名单 | 官方认可币种、保证金币种、报价 token |
| 域名参数 | 域名注册价、市场手续费、广告费率、押金规则 |
| 模块开关 | 消息模块、信用分记录、C 位奖励、快速成交入口 |

建议流程：

```text
1. D 席位发起常规提案。
2. 进入 48 小时否决窗口。
3. 任意 D 席位否决，提案失败。
4. 48 小时内无人否决，提案通过。
5. 具备执行权限的席位 / executor 执行上链。
```

常规提案不能直接替换核心合约，不能迁移 treasury，不能迁移 mint 权限。这些属于重大提案。

---

## 8. 重大提案

重大提案用于高风险变更。

典型范围：

| 类型 | 例子 |
| --- | --- |
| 合约升级 | 新 Factory、新模板、新模块 |
| 核心权限迁移 | treasury、mint、recorder、owner、admin |
| 分红规则重写 | 改变 D 分红逻辑、开轮权限、领取公式 |
| 信用体系迁移 | 更换 CreditGraph、迁移信用分 |
| D 规则变更 | 总量、精度、席位门槛、转让限制 |

建议流程：

```text
1. D 席位发起重大提案。
2. 第一重：D 席位进入 120 小时否决窗口。
3. 如果 D 席位没有否决，开放官方 DealInfoNFT 用户否决。
4. 第二重：有效治理 NFT 在窗口期内可以否决。
5. 任意一边达到否决条件，提案失败。
6. 两边都未触发否决，到期后可以执行。
```

重大提案需要两道保护：

```text
D 席位代表协议权益层。
官方 DealInfoNFT 代表真实使用者。
重大变更不能只对一边负责。
```

---

## 9. 官方 NFT 用户否决

重大提案会接入官方 `DealInfoNFT` 的用户否决。

| 项目 | V1 规则 |
| --- | --- |
| 参与 NFT | 只认官方 `DealInfoNFT` |
| 外部 NFT | 不参与治理 |
| 计票方式 | 一枚有效治理 NFT = 一票 |
| 是否按信用分加权 | V1 不做 |
| 是否按 owner 去重 | V1 不去重 |
| 否决阈值 | 有效治理 NFT 的 20% |
| 活跃窗口 | 默认 90 天 |

有效治理 NFT 不建议按全部铸造 NFT 总量计算。原因是沉默 NFT 越多，20% 越难达到，用户否决会失效。

建议有效治理 NFT 定义：

```text
官方 DealInfoNFT
且在最近 90 天内有治理活跃记录
```

活跃行为包括：

| 行为 | 是否记为活跃 |
| --- | --- |
| 成功完成 deal | 是 |
| 发起 deal | 是 |
| 参与 deal | 可接入 |
| 领取分红 | 是 |
| 参与治理否决 | 是 |
| 单纯长期持有 NFT | 不一定有效 |

---

## 10. NFT 否决快照

NFT 否决也使用快照，防止提案期间临时买卖刷票。

```text
提案创建时，谁持有这个官方 NFT，谁对这条提案有否决权。
提案创建后 NFT 可以继续转让。
新 owner 不能投这条旧提案。
新 owner 从下一条新提案开始拥有投票权。
同一个 tokenId 对同一条提案只能投一次。
```

## 11. 示例流程

### 11.1 一次分红

```text
本月协议收入进入 treasury。
运营把可分配部分换成 50,000 DC。
D 席位发起分红提案。
无人否决后，executor 创建一轮 50,000 DC 分红。
系统记录 D 持仓快照。
用户按自己快照时的 D 持仓比例领取。
```

如果某用户持有 3 D：

```text
3 / 100 * 50,000 = 1,500 DC
```

### 11.2 一次常规参数调整

```text
席位钱包提案：把某项手续费从 0.3% 调到 0.25%。
进入 48 小时窗口。
如果没有 D 席位否决，到期后执行。
如果任意 D 席位否决，提案失败。
```

### 11.3 一次重大升级

```text
席位钱包提案：替换核心交易模板。
进入 120 小时窗口。
D 席位可以否决。
官方有效 NFT 用户也可以否决。
如果 D 席位或 NFT 用户任何一边触发否决，提案失败。
如果都没有否决，到期后执行。
```

## 12. DAO 使用案例

### 12.1 调整交易手续费

场景：

```text
当前点对点交易手续费是 0.3%。
团队希望把手续费调整为 0.25%，降低用户交易成本。
```

流程：

```text
1. 持有 2.5 D 以上的席位钱包发起常规提案。
2. 提案内容写清楚：把交易手续费从 0.3% 调整到 0.25%。
3. 进入 48 小时否决窗口。
4. 如果任意 D 席位认为不合理，可以否决，提案失败。
5. 如果 48 小时内无人否决，提案通过。
6. executor / 有权限账户执行参数修改。
7. 前端读取新参数，后续交易按 0.25% 收费。
```

适用原因：

```text
手续费属于日常运营参数。
它影响用户成本，但不改变协议核心所有权和资产安全。
所以走常规提案即可。
```

### 12.2 发起一次协议分红

场景：

```text
本月 treasury 收到协议收入。
其中一部分资产已经被多签或运营兑换成 50,000 DC。
团队希望把这 50,000 DC 分给 D 持有人。
```

流程：

```text
1. treasury / dividendSource 授权分红合约使用 50,000 DC。
2. 持有 2.5 D 以上的席位钱包发起分红提案。
3. 提案写清楚：本轮分红总额 50,000 DC，资金来自 treasury。
4. 进入否决窗口。
5. 如果没有 D 席位否决，提案通过。
6. executor 调用 createRound(50,000 DC) 创建分红轮。
7. 合约记录 D 持仓快照。
8. D 持有人在前端看到可领取额度，并自行 claim。
```

用户领取例子：

```text
D 总量 = 100
本轮分红 = 50,000 DC
用户快照时持有 3 D

用户可领取 = 3 / 100 * 50,000 = 1,500 DC
```

注意：

```text
D 席位可以发起分红提案。
但不能绕过 DAO 直接开分红轮。
分红资金来自 treasury / dividendSource，不来自提案人的个人钱包。
```

### 12.3 替换核心合约模板

场景：

```text
团队开发了新的 Deal 模板。
新模板已经完成测试和审计。
需要把 Factory 的模板地址切换到新版本。
```

流程：

```text
1. 持有 2.5 D 以上的席位钱包发起重大提案。
2. 提案内容写清楚：旧模板地址、新模板地址、升级原因、审计结论。
3. 进入 120 小时 D 席位否决窗口。
4. 如果任意 D 席位否决，提案失败。
5. 如果 D 席位没有否决，进入官方 DealInfoNFT 用户否决阶段。
6. 有效治理 NFT 持有人可以对该重大升级投否决。
7. 如果 NFT 否决达到有效治理 NFT 的 20%，提案失败。
8. 如果两边都没有触发否决，到期后 executor 执行模板替换。
9. 新创建的 deal 使用新模板，旧 deal 继续按旧合约逻辑运行。
```

适用原因：

```text
核心模板替换会影响后续所有交易。
它不是普通参数调整。
所以必须走重大提案，并同时接受 D 席位和官方 NFT 用户的双重否决。
```

### 12.4 修改域名广告费率

场景：

```text
域名广告消耗速度过快或过慢。
团队希望调整广告费率规则。
```

流程：

```text
1. D 席位发起常规提案。
2. 提案写清楚新费率、适用范围、修改原因。
3. 进入 48 小时否决窗口。
4. 无人否决后执行参数修改。
5. 新的域名广告充值和消耗按新规则计算。
```

注意：

```text
如果只是调整费率，属于常规参数。
如果要迁移 DCDomainRank 合约、迁移 treasury 或更换 reporter 权限，则属于重大提案。
```

## 17. 对外总结

```text
D 是固定 100 枚的协议权益代币。
```

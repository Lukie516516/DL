DEAL 是怎样运作的？

它不是一个单纯的交易网站。DEAL 想做的，是把“两个人谈好的一笔交易”，变成一份能自动保管资产、记录过程、按约定结算的链上协议。

01 / 一句话

把信任放进规则，而不是放在中间人手里

DEAL 把每一笔交易单独变成一个“小型数字保管箱”。双方的资产、操作和时间条件都由同一套规则管理。

“不需要相信对方会不会变卦，只需要双方事先确认同一套条件。”

前端是交互入口，但不是记账中心。即使换一个前端，已经创建的交易、资产和状态仍在链上。

30 秒版：DEAL 的核心不是“平台替你判断”，而是“双方先写清条件，系统再按条件执行”。它将资产保管、履约状态、超时处理和信用记录放进一个可验证的公共系统。
02 / 一笔交易

从谈好条件，到自动结算

无论交易的是代币、NFT，还是单方付款与无资产承诺，核心都是同一个有起点、过程和终点的状态流程。

1

写清条件

谁与谁交易、交什么、数量多少、有效时间多长。

双方共享同一份条款
2

创建协议

工厂按交易类型创建一个独立的交易实例，不与其他订单混在一起。

每单隔离，互不影响
3

锁定资产

代币或 NFT 进入这笔交易自己的合约，不进入平台人工账户。

不等于转给对方
4

双方履约

接受、确认、追加条件、取消或超时处理，都受当前状态约束。

不能跳过必要步骤
5

结算与留痕

条件满足后交换资产；不满足时按规则退回。结果同步进入活动与信用记录。

过程可追溯
用大白话说这像一台不偏向任何一方的自动保管柜：只有约定的条件成立，柜门才会按约定的方向打开。
被问“如何防止一方拿钱不办事”时：资产先锁在单笔交易的合约中，合约只认状态和条件。如果没达到结算条件，就不会把资产交给另一方；超时后走预先定义的退回或取消路径。
03 / 不只是交易

四个系统，组成一个协议生态

DEAL 把执行、身份、价值和公共决策拆开，让每一层各自承担明确的职责。

I.

交易协议引擎

负责创建订单、保管资产、推进状态、处理超时与结算。不同资产组合由不同模板承接。

代币 ↔ 代币代币 ↔ NFT单方支付开放接单
II.

身份与域名

DealInfoNFT 是链上身份与信用载体；域名是用户或商家的公开门面，可以聚合交易、展示排名和设置访问条件。

身份 NFT信用记录域名市场活跃度
III.

价值循环

交易可使用多种资产。DC 承担协议内的费用、激励和价值流通；流动性池负责兑换与定价路径；部分费用进入国库或执行销毁。

DC流动性池手续费路由国库
IV.

DAO 与协议升级

参数调整、国库支出、核心升级和跨链指令通过不同级别的提案处理。升级保留原地址与历史数据，只更换经治理批准的逻辑。

提案质押否决精确权限
04 / 三种凭证

DC 管流通，D 管权益，NFT 管身份

三者不是三个名字不同的代币，而是三类不同的权利与职责。

DC

DealCoin

日常流通与激励工具。可用于协议费用、奖励、流动性和分红资产。

可流通 · 可增发/销毁 · 多链各自运行
D

协议权益

固定 100 D。主要用于 ETH 主网治理、席位、否决和 DC 分红权重，1 D 对应 1% 权重。

固定总量 · ETH 主网 · 权益与治理
ID

DealInfoNFT

官方链上身份。承载用户身份、交易活跃与信用信息，并在重大治理中提供用户侧约束。

一个 NFT 一个身份 · 可验证 · 可组合
常见误解：DC 不等于“股权”，D 也不是日常支付币。这种分工是为了避免“为了交易就必须稀释治理权”，也避免“治理币剧烈流通导致决策权不稳定”。
05 / DAO

把“谁能改系统”也写成公开规则

技术上可升级，不代表某个人可以随意升级。DEAL 把不同风险的动作分级，并限定提案可以调用的目标、功能和金额。

不是“投票后什么都能做”

每类提案只能进入对应的执行通道。提案必须匹配已登记的合约地址和具体功能，超出边界就无法执行。

参数类 · 日常费率和运营参数
国库类 · 明确资产、收款人和数量
重大类 · 升级、新模块和跨链能力
高安全储备 · 以更高门槛动用
1

提案把行为写清楚

标题和内容给人看；目标合约、金额和调用数据给系统执行。

2

不同风险，不同门槛

通过时间窗口、D 质押、席位否决与活跃 NFT 参与组合制衡。

3

执行前再校验

政策注册表检查“这一类提案能否调用这一个功能”，防止任意调用。

4

结果链上留痕

谁提、支持多少、是否否决、调了什么，都能按交易记录核验。

06 / 跨链

一个治理中心，多条业务链执行

跨链在这里主要传递的是“已经通过的治理指令”，不是默认把用户资产在链之间搬来搬去。

Ethereum 主网 DAO

提案、D 治理、主网分红和高安全储备的核心决策中心。

⇄

BSC / Base / 未来副链

各链本地部署协议、本地国库与执行器，只执行白名单内且获得足够独立通道确认的指令。

通道 A ✓
通道 B ✓
通道 C
2-of-3 的含义三条独立消息通道中，至少两条对同一指令给出一致确认，副链才执行。单一跨链服务中断或异常，不应单独决定系统行为。
被问“跨链是不是把钱跨过去”时：我们当前强调的是“治理跨链”。例如 ETH DAO 决定更新 Base 的某个参数，多通道传递同一条指令，Base 执行器确认后在本地执行。它与用户资产桥是两个不同问题。
07 / 安全思路

安全不靠一道锁，而靠多层边界

DEAL 的安全目标是尽量把“可以做什么”缩小，并在变更前重现真实链上环境。

交易状态机

每个操作只能在正确状态发生。不允许跳步、重复结算或非交易参与者操作资产。

权限最小化

治理与跨链执行器按目标合约和具体功能白名单放行，不把“任意调用”当作快捷方案。

主网分叉预演

升级前复制主网当前状态，检查历史数据、地址关系和业务参数在升级前后是否一致。

单笔交易隔离

用轻量化独立实例承载每笔交易。某个订单的资产和状态不与其他订单共用一个资金池。

可升级但可追溯

代理保留地址和数据，实现逻辑经治理更换。升级交易和新逻辑地址均在链上可查。

分红防重复领取

每一轮按权益和领取记录独立结算。同一份权益不能通过领取后转账的方式在同一轮内重复支取。

一个需要说清的边界

测试、静态检查和主网分叉预演可以显著降低风险，但不应被表述为“绝对安全”。智能合约、底层公链、跨链服务、用户私钥和治理参与度仍各自存在风险。独立第三方审计是与内部测试不同的另一道保障。

08 / Q & A

技术交流常见追问

点开问题即可查看建议回答。回答保留技术含量，但不陷入合约代码细节。

DEAL 和普通中心化平台最大的不同是什么？
中心化平台用自己的数据库和客服规则来保证交易；DEAL 用双方共同确认的链上状态和资产保管规则来保证交易。前端可以改版，但不能靠改页面篡改已经在链上的交易结果。
钱和 NFT 到底存在哪里？
在履约期间，资产由这一笔交易自己的智能合约保管，不是转进团队的私人钱包。最终只能按状态机转给约定参与方或退回原所有者。
为什么不把所有交易放在一个大合约里？
每单独立能让资产和状态天然隔离，也更容易从地址层面追溯。Factory 使用轻量化克隆方式创建实例，无需每次完整复制所有代码，兼顾隔离与成本。
如果合约需要修复，是否要迁移所有数据？
核心模块采用代理地址 + 实现逻辑的可升级设计。地址和历史存储保留，经治理完成后更换实现逻辑。升级前会比较存储布局并在主网分叉上重放业务流程。
DAO 如何防止恶意提案任意调用合约？
提案通过后仍要经过政策注册表。它会检查提案类型、目标合约、具体函数、转账价值以及是否需要检查内嵌的跨链动作。不符合规则的 action 无法执行。
跨链消息如果有一家服务出问怎么办？
副链执行不依赖单一通道。对同一指令，至少两条独立通道提供一致确认才会触发。消息还需通过来源、目标白名单和唯一消息标识校验，防止伪造和重放。
分红后把 D 转给别人，能不能再领一次？
不能在同一轮用同一份权益重复领取。分红轮使用该轮的权重与领取记录计算，并不是每次只看“当下钱包里有多少 D”。质押在治理中的 D 也会按规则计入权重。
前端查询链上数据为什么不会越来越慢？
链上事件适合审计，但不适合每次从创世区块扫到现在。DEAL 增加了 Reader 批量读取和链上索引模块，前端可以一次读取多条提案、交易、时间和排名数据；大规模场景仍可搭配链下索引器做缓存。
为什么需要区块链，普通数据库做不了吗？
普通数据库可以做出更快、更便宜的用户体验，但最终控制权在运营数据库的主体。DEAL 选择区块链，是为了让资产保管、状态变更、治理结果和升级记录可被多方独立验证。代价是 gas、确认时间和用户门槛。
你们可以说“已经完全安全”吗？
不应该。更准确的表述是：已经建立单元测试、权限负向测试、存储一致性检查、主网分叉预演和生产只读验证流程。这些能提高发现问题的概率，但不等于消灭所有未知风险，也不替代独立第三方审计。
09 / 当前边界

什么是当前系统，什么是继续建设

技术交流最重要的是不把“已验证”“已部署”和“已完全交权”混为一谈。

已建立的核心能力

  • 多类资产组合的点对点交易与状态结算
  • 身份 NFT、交易活动、信用与域名系统
  • ETH DAO V2、国库、主网 D 与 DC 分红模块
  • BSC 与 Base 的协议部署和多通道跨链治理路径
  • Reader/索引辅助的前端批量查询方案

持续完成的工作

  • 将剩余高权限操作逐步统一纳入 DAO 与精确策略
  • 每条新链继续做参数同步、国库标准化和端到端预演
  • Solana 紧凑架构继续测试，不把本地验证描述为已完成主网上线
  • 引入更多独立审计、监控和前端索引基础设施
  • D 分红与高安全储备保持在 ETH，副链不复制这两套业务

DEAL 的核心不是“发一个币”，而是建立一套可编程的交易关系。

它让陌生人、商家和社区可以在共同规则下交易，并让这套规则能够公开升级、跨链执行和持续治理。

# 合约体积与后续开发注意

## 1. 背景

当前部分核心合约已经接近 EVM 单合约 24KB 部署体积上限。

因此后续开发不能再按“哪里方便就往哪里加逻辑”的方式处理，尤其不能继续把新业务塞进已经拥挤的主合约。

当前最需要保护体积的合约：

| 合约 | 当前定位 | 后续原则 |
| --- | --- | --- |
| `DealRouter` | swap 主入口 | 已拆出 `DealRouterQuoter`，只保留成交入口 |
| `DealFactory` | deal 创建与核心接线 | 只做创建、权限、模块地址接线，不再承载新业务 |
| `DealOpenTokenToken` | 开放币币交易模板 | 不继续塞非交易主流程逻辑 |
| `DealAAssetNft` / `DealBAssetNft` | NFT 资产交易模板 | 公共结算、奖励、信用逻辑优先外拆 |
| `DealInfoNFT` | 官方身份 NFT | 已拆出 `DealInfoNFTRenderer`，主合约只保留数据 |
| `DCDomainRank` | 域名广告、排名、收益 | 新读取统计优先拆 reader，不继续堆主合约 |

## 2. Router 后续规则

`DealRouter` 不要求承载所有 swap 细节。

后续如果要加：

| 需求 | 推荐做法 |
| --- | --- |
| 新 swap 路径 | 新增独立 Router / Adapter |
| 新 preview 计算 | 拆到 Reader / Quoter |
| 新挂单策略 | 拆到 OrderBook / Strategy 合约 |
| 新资产入口 | 通过 Registry / PairManager 配置 |
| 前端聚合接口 | 新增只读 Reader，不塞进 Router |

`DealRouter` 后续只适合保留：

```text
1. 基础 swap 入口
2. 原生币包装/解包入口
3. 对 Pair / OrderBook 的轻量调用
4. 必要的安全校验
```

当前已经执行的拆分：

| 拆出模块 | 作用 |
| --- | --- |
| `DealRouterQuoter` | 承接 `previewExact0For1` / `previewExact1For0` / `preview0ForExact1` / `preview1ForExact0Net` |
| `DealInfoNFTRenderer` | 承接 `DealInfoNFT.imageOf` / `DealInfoNFT.tokenURI` 的 base64、JSON、SVG 渲染 |

不适合继续加入：

```text
1. 新业务规则
2. 复杂报价聚合
3. 大量 view 统计
4. 新排行榜逻辑
5. 新资产管理逻辑
6. 新治理逻辑
```

## 3. Factory 后续规则

`DealFactory` 后续只做核心工厂和模块接线。

允许保留：

```text
1. 创建 deal
2. 选择 deal implementation
3. 管理核心模块地址
4. 必要权限校验
5. 少量全局参数
```

不再新增：

```text
1. pair 管理逻辑
2. 排行榜逻辑
3. 域名广告逻辑
4. 复杂 reader 查询
5. 复杂奖励计算
6. 非 deal 创建主流程的新业务
```

新增功能优先拆到：

| 功能类型 | 推荐模块 |
| --- | --- |
| pair / TWAP / 虚拟流动性 | `DealPairManager` |
| 前端读取 | `DealReader` 或新的 Reader |
| 结果索引 | `DealResultIndex` |
| 过程时间线 | `DealActivityIndex` |
| 留言 | `DealMessageHub` |
| 域名排名 | `DCDomainRank` / Reader |
| swap 资产发现 | `DealSwapAssetRegistry` |

## 4. 新功能默认架构

以后新增功能时，默认按下面顺序判断：

```text
能做成 Reader 的，不进主合约。
能做成 Registry 的，不进 Factory。
能做成 Helper / Adapter 的，不进 Router。
能做成独立业务合约的，不进 Deal 模板。
只有必须读写核心状态的逻辑，才考虑进入核心合约。
```

## 5. 部署影响判断

| 改动位置 | 是否通常要重部署 | 影响 |
| --- | --- | --- |
| 新 Reader | 要部署新 Reader | 前端换读取地址 |
| 新 Registry | 要部署新 Registry | 前端/脚本换查询地址 |
| 新 Router / Adapter | 要部署新入口 | 前端换 swap 入口 |
| 修改 Factory | 要重部署 Factory 并重新接线 | 影响较大 |
| 修改 Deal 模板 | 要部署新 implementation | 只影响新创建 deal，旧 deal 不自动变化 |
| 修改 Pair | 不建议轻易做 | 涉及真实流动性 |
| 修改 Token / NFT 资产合约 | 不建议轻易做 | 涉及资产和历史数据 |

## 6. 一句话原则

```text
Router 和 Factory 以后只做入口和接线，不再承载新业务。
新功能优先外拆，避免核心合约再次逼近 24KB 上限。
```

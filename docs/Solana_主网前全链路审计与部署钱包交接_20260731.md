# Solana 主网前全链路审计与部署钱包交接

更新时间：2026-07-31

## 1. 当前结论

Solana 版本目前已经完成：

- 24 个生产程序的完整编译与持久 Localnet 部署。
- 生产形态的初始化、暂停开关、治理配置、国库、DC、DEX、域名、排行、身份、历史、终局和奖励接线。
- 真实资产移动、失败回滚、治理执行和程序升级权闭环。
- ETH 主网 fork 对照。
- Rust workspace、SDK、格式和 Clippy 全量回归。

但尚未在 Solana Mainnet 部署，也没有在 Solana Mainnet 发送任何交易。真实 ETH → Solana 的跨链传输、Relayer/桥接服务和 Mainnet 上的 2/3 消息确认仍未做现场验证。因此当前结论是：

> Localnet 的生产同构流程已经闭环；Solana Mainnet 尚未上线，不能描述为“主网全部部署完成”。

## 2. Solana 主网操作钱包

主网临时部署/付费钱包：

```text
BKGkPKypo6GNHZBqNLCCmryRKNjoi2iKvjCStzd2vgfQ
```

密钥只保存在本机仓库外：

```text
/Users/a1234/.config/solana/deal-mainnet-operator.json
```

文件权限为 `600`。私钥、助记词没有输出到终端、文档或 Git。

该钱包的定位是临时部署与支付交易费，不应长期持有协议核心管理权。正式初始化完成后：

- 业务配置 authority 应交给 Governance Executor PDA。
- Treasury controller 应交给 Governance Executor PDA。
- 24 个程序的 Upgrade Authority 应交给 Governance Executor PDA。
- 钱包只保留必要的剩余 SOL，不保留独立修改协议的能力。

2026-07-31 最新只读核验中，两个独立 Mainnet RPC 返回同一 genesis、仅相差 4 的近似 slot 和相同钱包余额；余额为 `0 SOL`。任何转账后仍必须重新从至少两个 RPC 只读核验余额。

Solana 的“owner”需要分层理解：

- `BKG...vgfQ` 是普通签名钱包，负责初次部署、创建状态账户和支付费用。
- Program account 的链上 owner 是 Upgradeable Loader，不是该钱包；真正可管理升级的是 ProgramData 的 Upgrade Authority。
- 协议 PDA 由各自程序拥有，不能由钱包直接任意转走或修改。
- 初始化期间 Upgrade Authority、业务 authority 和 Treasury controller 可以暂时由该钱包承担。
- 完成只读核验后，上述可变权限应全部交给 Governance Executor PDA，避免一个普通钱包成为永久超级管理员。

## 4. 本轮发现并修复的问题

| 编号 | 原问题 | 修复 | 是否改变原业务逻辑 |
|---|---|---|---|
| G-01 | Governance Executor 调用自身完成 authority 交接后，外层旧 `config` 会覆盖 CPI 内层的新 authority | 自调用 CPI 完成后执行 `config.reload()` 再写 nonce/执行状态 | 否。只防止旧账户缓存覆盖已成功的治理状态 |
| G-02 | Executor PDA 在外层账户中是只读，无法调用 `authority` 同时承担 payer 的治理方法 | 将 `executor_authority` 标记为可写 | 否。没有放宽 signer 或 authority 校验，只补足 payer 必需的写权限 |
| G-03 | 治理消息拒绝所有重复账户，导致两个资产都使用标准 SPL Token Program 时无法治理初始化 DEX | 只允许权限完全一致的同地址别名；writable/signer 权限不一致仍拒绝 | 否。只允许 Solana 合法的相同 Program ID 复用，没有允许权限提升 |
| I-01 | `create_domain_deal` 使用 Legacy Transaction 时为 1267 bytes，超过 Solana 1232 bytes 上限 | 改用 v0 Transaction + Address Lookup Table；实测压缩为 807 bytes | 否。合约参数、账户和原子 CPI 全部保留，只改变客户端交易封装 |
| I-02 | 本地治理客户端只能执行 IDL 内指令，无法验证 Upgradeable Loader | 增加受同一 envelope、2/3 确认和目标白名单约束的原始指令执行入口 | 否。治理合约规则未改变，测试工具仅能构造已有治理执行路径 |
| S-01 | 两个本地 Program ID 密钥文件曾是 `0644`，同机其他用户可读 | 将权限收紧为 `0600`，并在 Mainnet preflight 中对全部程序密钥及操作钱包强制检查 | 否。Program ID、公钥、二进制和链上逻辑均未变化，只修复本地密钥文件权限 |
| S-02 | Mainnet preflight 固定的 genesis hash 缺少末尾字符，导致正确的 Mainnet RPC 被误判 | 修正为 RPC 返回的完整 Mainnet genesis hash，并增加精确值回归测试 | 否。该问题只会安全地阻断只读检查/部署，不会把交易发送到错误链；业务合约未改变 |
| S-03 | 公共 RPC 并发执行多项 preflight 查询时会偶发断开，只返回笼统的 `fetch failed` | 改为顺序只读检查；只对超时、断连、429 和 5xx 做有限重试，并在错误中标明具体步骤 | 否。所有原检查项均保留，没有降低 Mainnet、钱包、余额、Program ID 或 hash 校验强度 |
| S-04 | workspace 整体 `--optimize-size` 可生成无入口点的 896-byte stub | 改为 24 个程序逐个独立构建，强制校验 SBF ELF machine 和非零 entry point，再选择更小有效产物 | 否。只防止无效构建产物进入部署清单 |
| O-01 | 24 个默认 `.so` 总计 8,633,576 bytes，主网 rent 较高 | 23 个程序使用尺寸优化产物；变大的 `deal_dex_quoter` 保留默认产物 | 否。Rust 源码、IDL、Program ID、指令和账户布局不变 |

没有修改以下业务规则：

- Deal 模板、创建门槛、加入模式、质押、投票、替换和终局判定。
- DC 手续费、C 严格最高信用选择、无 C 销毁规则。
- D、DC、身份 NFT、域名 NFT 的资产与冻结规则。
- Treasury 收款与打款权限。
- DEX 常数乘积、滑点和储备规则。
- 域名注册价格、市场手续费、黑名单、排行与大厅消息费。
- 分红快照和防双领规则。

## 7. 国库标准化收款说明

Solana 国库应采用统一行为：

- 原生 SOL：Treasury Vault PDA 可以直接接收。
- SPL Token：每一种 mint 都需要一个由 Treasury Vault PDA 所有的 Token Account/ATA。
- 任何人可以向已存在的 Treasury Token Account 转账。
- “协议产生手续费”不会自动进入国库；每个业务程序必须在结算路径中显式路由到对应的 Treasury Token Account。
- 不认识的 Token 不应自动作为协议收入统计；可以接收，但前端和会计层应区分“官方收入资产”和“误转/非官方资产”。
- 主网初始化时至少为 DC、官方稳定币和其他正式支持资产创建 canonical Treasury ATA，并记录在部署清单中。

## 8. 当前安全阻断项

### P0：Mainnet 前必须完成

1. 外部独立审计尚未完成。内部测试和 fork 不能替代第三方审计。
2. 真实 ETH → Solana 跨链运输尚未在公开网络闭环；当前 Localnet 2/3 signer 是本地测试密钥。
3. 最终 `.so`、IDL、程序 ID、初始化参数和 bridge signer/source 必须冻结并生成 hash manifest。
4. Mainnet 部署费用必须基于最终二进制重新计算并到账。
5. Mainnet 公共/付费 RPC、备用 RPC、交易重试和只读核验策略必须确定。
6. `create_domain_deal` 前端必须使用 v0 + ALT，不能回退到 Legacy Transaction。
7. Mainnet 完成初始化后，业务 authority、Treasury controller 和 24 个 Upgrade Authority 必须全部交给 Governance Executor PDA。

### 依赖风险

Solana SDK 的 `npm audit` 当前报告 3 个 moderate：

- `@solana/web3.js@1.98.4 -> jayson@4.3.0 -> uuid@8.3.2`
- 对应 `uuid` buffer bounds advisory：`GHSA-w5hq-g745-h8pq`
- 当前执行路径使用的是 RPC 请求 ID，不直接调用 advisory 所述的 `v3/v5/v6 + 外部 buffer`，但依赖树仍未达到零告警。

仓库根工具链的 `npm audit --omit=dev` 当前报告 24 项，其中 5 high、5 moderate。包括 `adm-zip`、`elliptic`、`lodash-es`、`undici` 和 `ws`。这些主要位于部署/测试工具依赖，但 Mainnet 签名环境同样需要供应链清洁，不能忽略。

本轮没有执行 `npm audit fix --force`，因为其建议包含破坏性版本变更，未经专项兼容测试不能直接用于主网工具链。

## 9. Mainnet 防误操作工具

新增两个主网专用脚本：

- `solana/sdk/mainnet-preflight.mjs`：只读校验 Mainnet genesis、明确指定的钱包、24 个 Program ID/二进制 hash、密钥文件权限、地址是否已占用、当前 rent、余额和 manifest hash。
- `solana/sdk/mainnet-deploy-programs.mjs`：只部署 24 个程序，不初始化、不交权、不 unpause；逐个 dump 回链上二进制并比对 SHA-256。

真实部署默认拒绝，必须同时满足：

- 明确的 Mainnet RPC 和备用 RPC。
- 钱包地址与 `SOLANA_MAINNET_EXPECTED_WALLET` 完全一致。
- 两个独立的真实写入确认字符串。
- 钱包余额达到 preflight 的实时预算。
- 人工批准的 manifest SHA-256 与现场 preflight 完全一致。
- 不允许使用固定 IP/DNS 绕过方式发送真实交易。

已经验证默认拒绝行为：

- 未设置 Mainnet RPC 时，preflight 在任何链调用前退出。
- 未设置真实部署确认字符串时，部署脚本在任何链调用前退出。
- 两个脚本均通过 `node --check`，SDK 回归为 23/23。

当前网络已经成功完成一次双 RPC 只读 preflight。公共 RPC 仍出现过偶发超时和参数限制，不能作为正式部署的生产基础设施；正式操作前仍需配置可信的主 RPC 和独立备用 RPC，并在转账及部署前重新生成预算和 manifest。

## 10. 下一步主网流程

在获得明确授权前，只做只读和本地工作。建议顺序：

1. 修复/隔离依赖告警，重新跑 ETH fork、Rust、SDK 和 Localnet 全套。
2. 外部审计与修复复审。
3. 冻结 commit、Rust/Solana/Anchor/Node 版本和可复现构建环境。
4. 生成 24 个 `.so`、IDL、Program ID 和 SHA-256 manifest。
5. 重新查询 Mainnet rent，形成精确 SOL 预算。
6. 给临时主网操作钱包转入预算 SOL，并从两个 RPC 只读确认。
7. 再次逐笔授权后，分批部署 Mainnet 程序，初始保持 paused。
8. 初始化 mint、PDA、Treasury ATA、DEX pair、治理、bridge signer 和 source。
9. 只读核验全部地址、代码哈希、参数、余额与 authority。
10. 小额 canary：DC/DEX/域名/国库/治理跨链消息。
11. 交接业务 authority、Treasury controller 和程序 Upgrade Authority。
12. 治理执行同版本 canary upgrade，验证 Mainnet 升级闭环。
13. 再次授权后分阶段 unpause。

任何“钱包收到 SOL”的事实都不自动构成部署授权。Mainnet 的部署、初始化、权限交接和 unpause 应分别确认。

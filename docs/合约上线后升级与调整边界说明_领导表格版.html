合约上线后升级与调整边界说明

面向产品、老板和部署负责人：说明上线后哪些东西可以调，哪些可以换，哪些不能动，以及 DAO 能执行到什么程度。

不是代理升级 已部署合约代码不能原地改写。
新逻辑主要影响新单 换模板 implementation 后，只影响新创建的 deal。
旧资产不能强改 已托管资产必须按原 deal 状态机处理。

1. 核心结论

问题 结论
是否能原地升级 不能。当前不是代理合约模式，已部署合约代码不可直接改写。
上线后如何调整 主要靠三种方式：调参数、换模块地址、换新模板实现。
旧 deal 是否自动升级 不会。已经创建出来的 deal clone 仍按旧代码运行。
新 deal 是否能用新逻辑 可以。Factory / Registry 指向新 implementation 后，新创建的 deal 使用新逻辑。
已托管资产能否被新代码改流向 不能。已经进旧 deal 的资产，必须按旧 deal 的状态机释放或成交。
DAO 能否自动执行升级 可以，但前提是 owner / admin / role 权限交给 Timelock / DAO。

2. 上线后调整方式

调整方式 怎么做 影响范围 难度 典型例子
调参数 调用已有 setXxx 方法 立即影响后续行为 低 手续费、消息费、域名价格、超时时间
换模块地址 部署新模块，再把 Factory / 入口合约指向新地址 后续调用走新模块 中 DealMessageHub、DealResultIndex、DealReader
换模板实现 部署新 deal implementation，再更新 registry 只影响新建 deal 中到高 新 DealOpenTokenToken、新资产 NFT 交易模板
重部署核心资产 部署新 token / NFT / 域名合约，并设计迁移方案 影响最大 高 重做 D、DL、DCDomain

3. 可直接调整的参数

模块 可调整内容 方法/入口 风险 说明
DealFactory 交易手续费、奖励比例 setFeesAndMintOnFees 低 适合 DAO 常规提案。
DealFactory 国库地址 setTreasuryByAdmin 中 钱流向变化，建议多签/DAO 执行。
DealFactory 消息费用、创建 burn 费用 setMessagePriceRule / setCreateBurnRule 低 可开关，可调金额。
DealFactory 超时、窗口时间 setMinTimeoutSeconds / setMinWindowSec 中 影响交易等待、强制处理和前端倒计时。
DealFactory 保证金币种、认可币种、入口权限 setAllowedMarginToken / setRecognizedTokens / setAllowedCreateFor 中 影响可交易资产和域名/大厅入口。
DealPairManager pair 手续费、虚拟流动性 setPairFee / setPairVirtualReserves 中到高 会影响报价，调错会影响价格。
DCDomain 域名注册价格、收款地址、支付币种 setBasePrice / setTreasury / setPaymentToken 中 支付币种变更需要前端同步。
DCDomainRank 最小充值、消耗速率、踢出时间 setMinDeposit / setBaseHourlyRate / setKickInactivitySeconds 中 影响域名排行和广告消耗。
DCDomainSwap B 方替换等待时间 setReplaceTimeoutSeconds 低 用于公开币币单顶替等待。
DealInfoNFT 铸造价格、图片大小限制、Factory 授权 setMintPriceU / setMaxImageDataBytes / addFactory 中 影响官方身份 NFT。
DealCreditGraph 信用 recorder 授权 setRecorder 高 谁能写信用分，必须严格管控。

4. 可替换模块

模块 能否替换 替换方式 旧数据影响 前端影响
DealReader 可以 部署新版，前端读新地址 不影响 换地址/ABI
DealMessageHub 可以 Factory 切 dealMessageHub 旧消息事件仍在旧 hub 换地址/事件来源
DealResultIndex 可以 Factory 切 dealResultIndex 旧索引不会自动迁移 换读取地址
DealActivityIndex 可以 Factory 切 dealActivityIndex 历史活动需迁移或双读 换读取地址
DealPairManager 可以 Factory 切 dealPairManager pair 映射/TWAP 状态需迁移 通常不直接接
DealImplementationRegistry 可以 Factory 切 dealImplementationRegistry 不影响旧 deal 一般不用改
DCDomainSwap 可以 部署新版，Factory/Rank 授权新地址 旧 Swap 创建的 deal 不变 换入口地址
DCDomainHall 可以 部署新版，Factory/Rank 授权新地址 旧 Hall 数据不自动迁移 换入口地址
DCDomainRank 可以 部署新版，Swap/Hall 指向新地址 充值/排行数据不自动迁移 换读取地址

5. 不能轻易动的部分

对象 是否能改 原因 正确处理方式
已创建的 deal clone 不能原地改 每个 clone 是独立合约，代码不可变 旧单按旧逻辑结束，新单走新模板
已托管资产的交易状态机 不能强行替换 直接关系到用户资产释放和成交 必须按旧状态机完成/取消/释放
NFT 资产托管逻辑 高风险 涉及 safeTransferFrom 和资产归属 只能做新版模板，必须审计
信用分核心公式 高风险 影响信用资产价值和 C 位收益 做迁移方案和公告，DAO 重大提案
DL 不建议改 协议主代币，涉及供应和权限 只谨慎授权 minter/pauser
D 基本不可改 总量、精度、席位门槛写死 改动基本等于重部署并迁移
DCDomain 不建议重部署 域名归属资产在这个 NFT 合约里 优先调参数或换外围模块

6. DAO 自动执行能力

DAO 动作 能否做 例子 前提
调参数 可以 改手续费、消息费、域名价格 owner/admin 权限交给 Timelock
切模块地址 可以 切 Hub、Index、PairManager Factory owner 归 DAO/Timelock
切模板实现 可以 Registry 指向新版 implementation Registry owner 归 DAO/Timelock
授权新模块 可以 授权新 Swap/Hall 创建 deal Factory/Rank owner 归 DAO/Timelock
授权增发 可以但高风险 给新 Factory MINTER_ROLE DL admin 必须是多签/DAO
改旧 deal 代码 不可以 旧 clone 原地升级 当前架构不支持
强改旧资产流向 不可以 让旧合约资产按新规则走 资产必须按旧状态机处理

7. 权限交接建议

权限对象 建议归属 原因
普通参数 owner/admin DAO Timelock 或多签 防止个人钱包单点风险。
DL 默认管理员 多签 / Timelock 控制增发、暂停等核心权限。
DealFactory owner Timelock 控制模块切换、费率、白名单。
DealImplementationRegistry owner Timelock 控制新 deal 模板使用哪个实现。
DealCreditGraph owner Timelock / 多签 控制谁能写信用分。
DCDomainRank owner Timelock / 多签 控制排行、充值和 reporter。
部署钱包 不建议长期持有核心权限 只用于部署，部署后应交权。

8. 升级分级

升级级别 适用内容 是否需要审计 是否需要前端配合 治理建议
常规参数 费率、价格、开关、白名单 一般不用完整审计 少量 常规提案
模块替换 Reader、Index、Hub、Rank、Swap、Hall 需要测试 需要 正式提案
模板升级 新 Deal implementation、OpenTT 状态机 需要完整审计 需要 重大提案
核心资产升级 D、DL、InfoNFT、DCDomain 必须审计 必须 重大提案 + 迁移方案

9. 给领导的一句话版本

维度 说明
升级方式 不是直接改旧合约，而是参数可调、模块可换、模板可换。
最容易动 手续费、消息费、域名价格、白名单、超时时间。
中等难度 Reader、Index、Hub、Rank、Swap/Hall 等模块替换。
高风险 交易模板、资产托管、信用公式、DL 增发权限。
不能做 已创建 deal clone 原地升级，也不能强行改变旧合约资产流向。
后续原则 Factory 少做事，Deal 模板只管交易，读取/索引/留言/排行放独立模块。

建议上线前完成权限交接：部署钱包只负责部署，核心 owner/admin/role 应迁到多签或 Timelock。否则 DAO 只能投票表达结果，不能自动执行链上调整。

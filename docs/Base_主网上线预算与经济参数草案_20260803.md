# Base 主网上线预算与经济参数草案

状态：已完成只读核验、Base mainnet fork 完整协议部署计费、Base V2 Executor 权限交接与 2-of-3 全链路预演。本文是待审阅草案，不是主网交易授权。

## 1. Base 侧 gas 实测

测量环境：Base mainnet fork，使用当时 Base L2 执行费和 L1 data fee。

| 阶段 | 交易数 | Gas used | L1 data fee | 实测 Base ETH 费用 |
| --- | ---: | ---: | ---: | ---: |
| 完整协议栈、Treasury、三池创建（不注资） | 62 | 79,858,659 | 0.000002272311901198 ETH | 0.000403869023951333 ETH |
| Base `DualBridgeExecutorV2` 部署、14 个目标白名单与完整权限交接 | 40 | 3,704,949 | 0.000000153086867395 ETH | 0.000019579688388629 ETH |
| 合计 | 102 | 83,563,608 | 0.000002425398768593 ETH | 0.000423448712339962 ETH |

以测量时 ETH `1,624.95 USD`、USD/CNY `6.7713` 换算：

- 实测合计约 `4.66 CNY`。
- 10 倍安全缓冲约 `0.00424 ETH`，约 `46.6 CNY`。
- 建议 Base 部署钱包准备 `0.01 ETH`，测量时约 `110 CNY`；它不是预计会花完的金额，而是为费率波动、重试、验证和后续权限交接留缓冲。

上述只是 Base 链上写入费。ETH DAO 发起 LayerZero / CCIP / Axelar 广播时，还会另外支付 Ethereum 侧跨链费。现有 Broadcaster 治理规则的 `maxValue` 为 `0.01 ETH`；Base 路由接线后必须先实时 `quoteFees`，再决定 BSC + Base 的合并预算。

同一套 40 笔交接在两次独立 fork 中的 `gasUsed` 都是 `3,704,949`；L1 data fee 随 Base 实时费率变化，上表采用第二次、较高的一次结果。

## 2. Base DC 发行模型

建议保持当前 ETH/BSC 结构：

- Base 部署一枚本链 DC，不把 ETH DC 直接当作可跨链锁定/铸造资产。
- Base `DealFactory` 保留 `MINTER_ROLE`，只用于协议成交奖励。
- Base `DualBridgeExecutorV2` 获得 DC `DEFAULT_ADMIN_ROLE` 和 `MINTER_ROLE`，ETH DAO 因此可以通过 2-of-3 跨链消息管理角色和执行明确 mint。
- 部署钱包在校验 Executor 可用后，放弃 DC 的 admin/minter 角色。
- Executor owner 转为 Executor 自身；Factory owner、Factory `crossChainGovernance`、Treasury controller 转为 Executor。
- Treasury bootstrap 只在 controller 交接验证后永久锁定。

该路径已在 Base mainnet fork 验证：部署钱包交接后无法直接改 Factory、mint DC、移动 Treasury、修改域名入口参数或修改 Executor；只有相同 payload 经 LayerZero / CCIP 两路确认后才能执行。

完整权限面不是只有 Factory/Treasury。必须同时交接：

| 模块 | 必须交给 Executor 的权限 |
| --- | --- |
| Executor 自身 | owner、LayerZero delegate、14 个 allowed target |
| DealFactory proxy | owner、admin、crossChainGovernance |
| DC | DEFAULT_ADMIN_ROLE、MINTER_ROLE、PAUSER_ROLE；Factory 保留协议奖励 MINTER_ROLE |
| ProtocolTreasury | controller；随后永久 lockBootstrap |
| DealInfoNFT | owner 和独立 admin 两套权限 |
| PairManager / OrderBook / AssetRegistry / DCDomainSwap | 自定义 owner |
| ImplementationRegistry / CreditGraph / DCDomain / DCDomainRank proxy / DCDomainMarket | Ownable owner |

`DCDomainHall`、MessageHub、ActivityIndex、ResultIndex、Renderer、Router/Quoter 和 Readers 没有治理 owner，或只绑定不可变协议地址，不存在需要移交的管理员权限。

本轮审计发现 `DCDomainSwap` 原来有 `onlyOwner` 参数入口，却没有 owner 移交函数。现已只增加标准 `transferOwner` 和事件；交易创建、超时范围、Factory/Domain/Rank 地址和用户资产流程均未修改。专门测试验证旧 owner 交接后失权、Executor 接管参数且三个协议引用保持不变。

## 3. 三池初始参数

当前 ETH/BSC 池的隐含初始价格约为：

`1 DC = 0.0001 USD`，即 `1 USDC/USDT = 10,000 DC`。

但旧池的对手资产真实余额几乎只有最小单位，主要依赖虚拟储备定价。虚拟储备可以改变报价，但不能代替真实兑付资产；`swap` 最终仍受真实 reserve 限制。

2026-08-03 用户确认：Base 的 Treasury DC 和三池初始化额度与现有链保持一致。由于 Base 的 USDC/USDT 精度和包装币类型与 Ethereum 一致，Base 精确复制 Ethereum 的初始参数，而不是复制 BSC 的 18 位稳定币/WBNB 数值：

| 池 | DC | 真实对手资产 | 虚拟对手储备 | 初始有效对手储备 |
| --- | ---: | ---: | ---: | ---: |
| DC/USDC | 5,000,000 DC | 0.000001 USDC（1 最小单位） | 499.999999 USDC | 500 USDC |
| DC/bridged USDT | 500,000,000 DC | 0.000001 USDT（1 最小单位） | 49,999.999999 USDT | 50,000 USDT |
| DC/WETH | 500,000,000 DC | 1 wei WETH | 31.999999999999999999 WETH | 32 WETH |

这与 Ethereum/BSC 的历史模式相同：有效储备用于定价，但真实对手资产只有 1 个最小单位。因此它不是 500 USDC、50,000 USDT、32 WETH 的真实兑付池；大量 DC 卖出仍会受真实余额限制并进入订单队列。该行为是本次“与其他链一致”决定的明确结果。

实际上线流程：

1. 先只创建三池，保持 `MAINNET_INIT_PAIRS=false`。
2. Base Treasury 初始获得 `5,000,000,000 DC`。
3. 三池分别获得 `5,000,000 + 500,000,000 + 500,000,000 = 1,005,000,000 DC`；Base 初始总供应量因此为 `6,005,000,000 DC`。
4. 三池各转入对应资产的 1 个最小单位，并使用上表 virtualOther 调用 `initPair`。
5. 逐池校验真实 reserve、virtual reserve 和 effective reserve，再开放前端交易。

Base 不部署 D、中本聪账户、DAO 或分红模块；副链 Treasury 是唯一的协议储备账户。

## 4. 跨链激活的特别注意

- Base route 先添加为 `active=false`，检查 LZ peer、CCIP selector/receiver、Axelar chain/address 后才激活。
- Executor 初次部署时暂由部署钱包持有 owner；先完成 bridge 配置和无资产 canary，再交接所有生产模块。`Executor.transferOwnership(self)` 必须是最后一笔本地权限交易。
- Executor 自持 owner 后，后续白名单、阈值和桥参数也必须通过现有 2-of-3 跨链治理修改；这是消除部署钱包后门的结果，同时意味着不能在只剩一路桥可用时临时救援。
- Base 激活后，Broadcaster 对每个 active chain 都要求一个 target。未包含 Base target 的旧广播 calldata 将 revert，因此激活前必须排查未执行提案。
- 首次 canary 只对无资产 Probe 做同值写入，不调 Factory、DC、Treasury 或三池。
- canary 需要 LayerZero / CCIP / Axelar 任意两路确认，并验证只执行一次。
- Base canary 通过前，不执行 DC mint、Treasury 打款、池初始化或生产参数修改。

## 5. 待确认点

已确认：Base 本链独立 DC、Treasury `50 亿 DC`、三池复制 Ethereum 历史初始化参数，且 Base 不设中本聪账户/分红。

仍需操作性确认：

1. 向 `0xE88c...9893` 的 Base 主网地址转入至少 `0.01 Base ETH`；当前余额为 0。
2. 同一地址准备至少 1 最小单位 Base USDC（`0x8335...2913`）和 1 最小单位指定桥接 USDT（`0xfde4...9bb2`）；当前两者余额均为 0。建议实际各转入至少 `0.01`，初始化只使用 `0.000001`。
3. canary 通过后让 Executor 自持 owner，正式取消部署钱包紧急管理权。

初始化工具 `npm run base:economics:init` 默认只读，检查完整供应量归属、池映射、token 顺序、余额上限和虚拟储备；显式设置 `BASE_MAINNET_INITIALIZE=1` 后才执行，并按目标差额续跑，防止中断后重复 mint。完成记录写入后，工具自动转为 audit-only，不再补发 Treasury 或池余额。

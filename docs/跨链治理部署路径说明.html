2
一笔治理消息的完整旅程

① 提案创建（ETH 主网）

NFT 持有者在 DealGovernance 发起提案，内容是「调用 CrossChainBroadcaster.broadcast(chainIds[], targets[], calldata, gasLimit)」。每条目标链都要填自己的业务合约 target，投票周期结束，赞成票超过 quorum。

② 提案执行 → 广播（ETH 主网）

任何人调用 DealGovernance.execute()，触发 CrossChainBroadcaster.broadcast()。该函数会按目标链分别构造 payload：abi.encode(nonce, targetOfThisChain, calldata)。这样 BSC / Polygon / 其他链上的业务合约地址可以不同。

③ 三路传输（桥协议层）

LayerZero ~60 秒到；Wormhole ~2 分钟到；Axelar ~3 分钟到。每条桥独立，互不依赖。任何一条暂时故障不影响其余两条。

④ 到达确认（BSC 主网）

DualBridgeExecutor 收到每条桥的消息后，计算 msgHash = keccak256(nonce, target, calldata)，标记对应桥已确认。

⑤ 阈值触发 → 执行（BSC 主网）

当 confirmed 数量 ≥ threshold（默认 2），立即调用 target.call(calldata)。DealFactory 收到调用后更新参数或切换合约地址。

⑥ 防重执行锁

执行前设 executed[msgHash] = true。第三条桥（或任何后续消息）到达时，第一行检查 if (executed[msgHash]) revert AlreadyExecuted，完全不执行。

5
安全机制与边界保护

来源验证（三重）

LZ：OApp peers 白名单，只接受注册的 ETH 对端地址。
WH：验证 msg.sender == wormholeRelayer + srcChain + srcAddress。
AX：axelarGateway.validateContractCall() + 来源链/地址字符串双重匹配。

执行目标白名单

allowedTargets[target] 必须为 true 才执行。DAO 无法通过跨链治理调用任意合约，只能调用已登记的合约。

防重放（nonce + hash 锁）

每条消息 msgHash = keccak256(nonce, target, calldata)，执行后永久设 executed[msgHash] = true，任何后续到达的同一消息直接 revert。

无双执行竞态

区块链串行执行。即使两条桥消息在同一区块，先处理的交易执行并设锁，后处理的交易在第一行即被拒绝。


边界场景速查

场景结果原因
第3条桥姗姗来迟
 忽略 executed[hash] = true，第一行 revert
LZ + WH 同一区块到达
 执行一次 先处理的 tx 执行并上锁，后处理的 tx revert
同一条桥重复发相同消息
 不累加 confirmed[hash][BRIDGE_LZ] 是 bool，置 true 是幂等的；count 从头重新数
calldata 写错，target 内部 revert
 标记已执行，不重试 executed[hash] 在 call 前已设为 true；失败后需要用新 nonce 重新广播
某条桥完全宕机
 另外两桥仍可执行 threshold=2，任意两桥即可；三桥独立，互不阻塞

一次典型治理提案的时间线
时间发生什么链
T+0 NFT 持有者发起提案（如「将平台手续费从 1% 改为 0.8%」） ETH 主网
T+3天 投票结束，赞成票达 quorum，提案通过 ETH 主网
T+3天 + 时间锁 任何人调用 execute()，触发 CrossChainBroadcaster.broadcast() ETH 主网
T + ~1分钟 LayerZero 消息到达 DualBridgeExecutor，LZ=true，count=1/2 BSC 主网
T + ~2分钟 Wormhole 消息到达，WH=true，count=2，达到 threshold=2 → 触发 DealFactory.setFeeRate() BSC 主网
T + ~3分钟 Axelar 消息到达，axConfirmed=true 但 executed=true，直接忽略 BSC 主网
⚠️
在 owner 移交前必须做冒烟测试 部署完成后，先在 owner 移交前用部署者钱包手动调用 broadcast() 发一条测试消息（比如 setParam(999)），确认 BSC 端正常收到并执行，再做 transferOwnership。一旦移交，只能通过 DAO 提案找回控制权。

# 合约上线后升级与调整边界说明

## 1. 核心结论

| 问题 | 结论 |
| --- | --- |
| 当前是否是代理升级模式 | 不是。已部署合约代码不能原地改写 |
| 上线后还能不能调整 | 可以，但主要通过调参数、换模块地址、换新模板实现 |
| 旧 deal 会不会自动升级 | 不会。已经创建的 deal clone 仍按旧代码运行 |
| 新 deal 能不能用新逻辑 | 可以。Factory / Registry 指到新 implementation 后，新创建的 deal 用新逻辑 |
| 已托管资产能不能被新代码强行改变 | 不能。已托管资产必须按原 deal 状态机释放或成交 |
| DAO 能不能自动执行升级 | 可以，但前提是 owner/admin/role 权限交给 Timelock / DAO |

## 2. 三种上线后调整方式

| 调整方式 | 怎么做 | 影响范围 | 难度 | 典型例子 |
| --- | --- | --- | --- | --- |
| 调参数 | 调用已有 `setXxx` 方法 | 立即影响后续行为 | 低 | 手续费、消息费、域名价格、超时时间 |
| 换模块地址 | 部署新模块，再把 Factory / 入口合约指向新地址 | 后续调用走新模块 | 中 | 换 `DealMessageHub`、`DealResultIndex`、`DealReader` |
| 换模板实现 | 部署新 deal implementation，再更新 registry | 只影响新建 deal | 中到高 | 新 `DealOpenTokenToken`、新资产 NFT 交易模板 |
| 重部署核心资产 | 部署新 token / NFT / 域名合约 | 影响最大，需要迁移 | 高 | 重做 `D`、`DL`、`DCDomain` |

## 3. 最容易调整的配置类

| 合约/模块 | 可调整内容 | 调整方式 | 风险等级 | 备注 |
| --- | --- | --- | --- | --- |
| `DealFactory` | 交易手续费比例 | `setFeesAndMintOnFees` | 低 | 适合 DAO 常规提案 |
| `DealFactory` | DC/DL 奖励比例 | `setFeesAndMintOnFees` | 低 | 影响后续成交奖励 |
| `DealFactory` | 国库地址 | `setTreasuryByAdmin` | 中 | 钱流向变化，建议多签/DAO |
| `DealFactory` | 消息费用 | `setMessagePriceRule` | 低 | 可开关、可调价格 |
| `DealFactory` | 创建 deal burn 费用 | `setCreateBurnRule` | 低 | 可开关、可调价格 |
| `DealFactory` | 最小超时时间 | `setMinTimeoutSeconds` | 中 | 影响交易等待/强制处理 |
| `DealFactory` | 最小窗口时间 | `setMinWindowSec` | 中 | 影响时间窗口规则 |
| `DealFactory` | 保证金币种白名单 | `setAllowedMarginToken` | 中 | 涉及可托管资产 |
| `DealFactory` | 认可币种 | `setRecognizedTokens` | 中 | 影响报价、手续费和信用计算 |
| `DealFactory` | 域名/大厅等入口权限 | `setAllowedCreateFor` | 中 | 控制谁能代用户创建 deal |
| `DealPairManager` / Pair | pair 手续费 | `setPairFee` | 中 | 影响 swap/报价 |
| `DealPairManager` / Pair | 虚拟流动性 | `setPairVirtualReserves` | 中到高 | 调错会影响价格 |
| `DCDomain` | 域名注册价格 | `setBasePrice` | 低 | 常规运营参数 |
| `DCDomain` | 域名收款地址 | `setTreasury` | 中 | 钱流向变化 |
| `DCDomain` | 域名支付币种 | `setPaymentToken` | 中 | 前端需同步 |
| `DCDomainMarket` | 二级市场手续费 | `setFeeBps` | 低 | 有上限 |
| `DCDomainMarket` | 手续费接收地址 | `setFeeRecipient` | 中 | 钱流向变化 |
| `DCDomainRank` | 最小充值金额 | `setMinDeposit` | 低 | 域名广告/排行参数 |
| `DCDomainRank` | 基础消耗速率 | `setBaseHourlyRate` | 中 | 影响 DC 消耗 |
| `DCDomainRank` | 充值影响倍率 | `setDepositRateBps` | 中 | 影响排行衰减/消耗 |
| `DCDomainRank` | 踢出不活跃时间 | `setKickInactivitySeconds` | 中 | 影响域名大厅体验 |
| `DCDomainSwap` | B 方替换等待时间 | `setReplaceTimeoutSeconds` | 低 | 当前用于公开币币单 |
| `DealInfoNFT` | 身份 NFT 铸造价格 | `setMintPriceU` | 中 | 影响身份 NFT 发行 |
| `DealInfoNFT` | 图片大小限制 | `setMaxImageDataBytes` | 低 | 防止链上数据过大 |
| `DealCreditGraph` | 信用 recorder 授权 | `setRecorder` | 高 | 谁能写信用分，必须谨慎 |

## 4. 可以替换但要重新接线的模块

| 模块 | 能否替换 | 替换方式 | 是否影响旧数据 | 前端是否要改 |
| --- | --- | --- | --- | --- |
| `DealReader` | 可以 | 直接部署新版，前端读新地址 | 不影响 | 要换地址/ABI |
| `DealMessageHub` | 可以 | 部署新版，Factory `setGlobal("dealMessageHub", newHub)` | 旧消息事件仍在旧 hub | 要换地址/事件来源 |
| `DealResultIndex` | 可以 | 部署新版，Factory `setGlobal("dealResultIndex", newIndex)` | 旧索引不会自动迁移 | 要换读取地址 |
| `DealActivityIndex` | 可以 | 部署新版，Factory `setGlobal("dealActivityIndex", newIndex)` | 历史活动要迁移或双读 | 要换读取地址 |
| `DealPairManager` | 可以 | 部署新版，Factory `setGlobal("dealPairManager", newManager)` | pair 映射/TWAP 状态需迁移 | 一般不用直接接 |
| `DealImplementationRegistry` | 可以 | 部署新版，Factory `setGlobal("dealImplementationRegistry", newRegistry)` | 不影响旧 deal | 不一定 |
| `DCDomainSwap` | 可以 | 部署新版，Factory/Rank 授权新地址 | 旧 Swap 创建的 deal 不变 | 要换入口地址 |
| `DCDomainHall` | 可以 | 部署新版，Factory/Rank 授权新地址 | 旧 Hall 数据不自动迁移 | 要换入口地址 |
| `DCDomainRank` | 可以 | 部署新版，Swap/Hall 指向新地址 | 充值/排行数据不自动迁移 | 要换读取地址 |

## 5. Deal 模板升级边界

| 对象 | 能不能升级 | 对谁生效 | 说明 |
| --- | --- | --- | --- |
| 新的 deal implementation | 可以部署 | 新创建的 deal | 通过 registry 指向新 implementation |
| 旧的 deal clone | 不能原地升级 | 只按旧逻辑运行 | 每个 clone 是独立合约 |
| 新交易状态机 | 可以做新版模板 | 新创建的 deal | 需要完整测试和审计 |
| 旧交易状态机 | 不能强行替换 | 已存在 deal | 已托管资产必须按旧流程释放 |
| 新 OpenTokenToken 逻辑 | 可以部署新版 | 新 OpenTT deal | 旧 OpenTT 不变 |
| NFT 资产托管逻辑 | 可以做新版模板 | 新创建的 deal | 高风险，必须审计 |

## 6. 不建议频繁改的核心资产层

| 合约 | 当前定位 | 为什么不建议频繁改 | 如果必须改 |
| --- | --- | --- | --- |
| `DL` | 协议主代币 / 奖励 / burn | 涉及供应、增发、权限、用户资产 | 只能谨慎授权新 minter 或重部署迁移 |
| `D` | 分红权 / DAO 席位 | 总量、精度、席位门槛写死 | 改动基本等于重部署 D |
| `DealInfoNFT` | 官方身份 NFT / 信用载体 | 信用和身份绑定 tokenId | 可加授权 Factory，但不建议重部署 |
| `DCDomain` | 域名 NFT 本体 | 域名归属资产 | 重部署会导致老域名不在新合约 |
| 已创建 `Deal` clone | 单笔交易资产托管 | 代码不可变，且可能有资产在里面 | 只能按原流程走完 |

## 7. 最好不要继续堆逻辑的合约

| 合约 | 原因 | 后续建议 |
| --- | --- | --- |
| `DealFactory` | 已经接近核心路由和配置中心，体积也敏感 | 只保留创建、配置、权限、轻量路由 |
| `DealOpenTokenToken` | 模板体积接近上限，状态机复杂 | 新功能拆 helper 或新模板 |
| `DealRouter` | swap 路径和报价逻辑较重 | 复杂 swap 拆独立 router/helper |
| 各类 `Deal` implementation | 交易模板应专注资产流和状态机 | 留言、索引、排行、复杂奖励放外部模块 |
| `DL` | 主代币资产 | 保持稳定，只管 mint/burn/pause/permit |
| `D` | DAO/分红权资产 | 保持稳定，不要加复杂业务 |

## 8. DAO 可以自动执行什么

| DAO 动作 | 能不能做 | 示例 | 前提 |
| --- | --- | --- | --- |
| 调参数 | 可以 | 改手续费、消息费、域名价格 | owner/admin 权限交给 Timelock |
| 切模块地址 | 可以 | 切 `DealMessageHub`、`DealResultIndex` | Factory owner 归 DAO/Timelock |
| 切模板实现 | 可以 | Registry 指向新版 implementation | Registry owner 归 DAO/Timelock |
| 授权新模块 | 可以 | 给新 Swap/Hall 创建权限 | Factory/Rank owner 归 DAO/Timelock |
| 授权增发 | 可以但高风险 | 给新 Factory `MINTER_ROLE` | DL admin 归 DAO/多签 |
| 改旧 deal 代码 | 不可以 | 旧 clone 原地升级 | 当前架构不支持 |
| 强制改变旧 deal 资产流向 | 不可以 | 直接让旧合约资产走新规则 | 资产必须按旧状态机处理 |

## 9. DAO 权限结构建议

| 权限对象 | 当前应交给谁 | 原因 |
| --- | --- | --- |
| 普通参数 owner/admin | DAO Timelock 或多签 | 防止个人钱包单点风险 |
| `DL` 默认管理员 | 多签 / Timelock | 控制增发、暂停等核心权限 |
| `DealFactory` owner | Timelock | 控制模块切换、费率、白名单 |
| `DealImplementationRegistry` owner | Timelock | 控制新 deal 模板使用哪个实现 |
| `DealCreditGraph` owner | Timelock / 多签 | 控制信用 recorder |
| `DCDomainRank` owner | Timelock / 多签 | 控制排行、充值和 reporter |
| 部署钱包 | 不建议长期持有核心权限 | 只用于部署，部署后应交权 |

## 10. 升级分级建议

| 升级级别 | 适用内容 | 是否需要审计 | 是否需要前端配合 | 是否建议 DAO |
| --- | --- | --- | --- | --- |
| 常规参数 | 费率、价格、开关、白名单 | 低，一般不用完整审计 | 少量 | 可以常规提案 |
| 模块替换 | Reader、Index、Hub、Rank、Swap、Hall | 需要测试 | 需要 | 应走提案 |
| 模板升级 | 新 Deal implementation、OpenTT 状态机 | 需要完整审计 | 需要 | 应走重大提案 |
| 核心资产升级 | D、DL、InfoNFT、DCDomain | 必须审计 | 必须 | 必须重大提案 |

## 11. 给领导的一句话版本

| 维度 | 说明 |
| --- | --- |
| 升级方式 | 不是直接改旧合约，而是参数可调、模块可换、模板可换 |
| 最容易动 | 手续费、消息费、域名价格、白名单、超时时间 |
| 中等难度 | Reader、Index、Hub、Rank、Swap/Hall 等模块替换 |
| 高风险 | 交易模板、资产托管、信用公式、DL 增发权限 |
| 不能做 | 已创建 deal clone 原地升级、强行改变旧合约资产流向 |
| 后续原则 | Factory 少做事，Deal 模板只管交易，读取/索引/留言/排行放独立模块 |

## 12. 后续开发原则

| 原则 | 具体做法 |
| --- | --- |
| 新功能不要塞 Factory | 新增独立模块，再由 Factory 接线 |
| 新交易逻辑不要硬改旧模板 | 做新 implementation，只让新 deal 使用 |
| 前端读数据不要扫链 | 新增 Reader / Index view 接口 |
| 治理参数统一管理 | 写入 DAO 参数清单 |
| 重大升级先审计 | 代码、部署脚本、接线文档、回滚方案一起准备 |
| 上线前交权 | owner/admin/role 迁到多签或 Timelock |

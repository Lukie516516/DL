DAO / Dividend / Governance

让协议收入、治理权和用户保护机制形成闭环

这份文档用于给产品、运营、管理层和开发同事统一说明 DealCoin（DC）项目的 D 代币、DAO 治理、协议分红和官方 NFT 用户否决机制。

一句话：

D 是固定 1000 枚的协议权益代币；持有 D 可以按比例领取协议分红；2.5 D 以上成为 DAO 席位；重大升级还要接受官方 DealInfoNFT 用户否决。

资产分工

DealCoin（DC）

协议主代币，负责交易奖励、支付、燃烧和生态流通。

D

协议权益代币，负责分红权、DAO 席位资格和治理否决权。

DealInfoNFT

官方身份 NFT，负责信用、交易身份和重大提案用户否决。

DealCoin（DC）负责生态流通。
D 负责协议权益。
DealInfoNFT 负责真实用户身份和治理用户侧保护。

D 代币规则

项目 V1 规则
总量固定 1000 D
精度8 位小数，类似 Bitcoin
是否可转让可以
是否可增发不可增发
分红权按持有比例领取协议分红
席位门槛持有 2.5 D 及以上
持有 1 D = 拥有协议 0.1% 的分红权。持有 2.5 D 或以上 = 拥有 DAO 席位资格。D 可以转让，但转让只影响未来分红和未来提案。

分红体系

分红只分协议收入。协议收入先进入 treasury 或指定的 dividendSource，最终建议统一换成 DealCoin（DC）后再分给 D 持有人。

来源 说明
交易手续费Deal 成交产生的协议手续费
域名收入域名注册、域名市场、域名广告等收入
其他协议收入后续新增模块产生的可分配收入

标准分红流程

1. 协议收入进入 treasury / dividendSource。
2. 运营、多签或 DAO 把可分红资产换成 DealCoin（DC）。
3. treasury / dividendSource 授权分红合约使用本轮 DealCoin（DC）。
4. D 席位发起分红提案。
5. 提案无人否决后，executor / DAO 执行账户创建分红轮。
6. 分红合约记录 D 持仓快照。
7. D 持有人按快照时的持仓比例领取 DealCoin（DC）。
D 席位可以发起分红提案，但不能绕过 DAO 直接创建分红轮。分红资金来自 treasury / dividendSource，不来自提案人的个人钱包。

快照机制

D 总量 = 1000
本轮分红池 = 10,000 DC
A 在快照时持有 1 D

A 可领取 = 1 / 1000 * 10,000 = 10 DC

DAO 治理模型

V1 采用“否决型治理”，不是传统多数赞成型投票。有人提出参数修改或重大变更，进入否决窗口；如果有合格席位否决，提案失败；如果没人否决，到期后可以执行。

提案类型 适用范围 流程
常规提案 手续费、Swap 参数、奖励参数、NFT 价格、消息费用、域名费率等日常运营参数 48 小时 D 席位否决；无人否决后执行
重大提案 合约升级、核心权限迁移、分红规则重写、信用体系迁移、D 规则变更 120 小时 D 席位否决 + 官方 NFT 用户否决

官方 NFT 用户否决

重大提案会接入官方 DealInfoNFT 的用户否决。外部 NFT 不参与治理。

项目 V1 规则
参与 NFT只认官方 DealInfoNFT
计票方式一枚有效治理 NFT = 一票
是否按信用分加权V1 不做
否决阈值有效治理 NFT 的 20%
活跃窗口默认 90 天
 
提案创建时，谁持有这个官方 NFT，谁对这条提案有否决权。
提案创建后 NFT 可以继续转让。
新 owner 不能投这条旧提案。
新 owner 从下一条新提案开始拥有投票权。
同一个 tokenId 对同一条提案只能投一次。

DAO 使用案例

调整交易手续费

当前点对点交易手续费是 0.3%，团队希望把手续费调整为 0.25%。

1. 持有 2.5 D 以上的席位钱包发起常规提案。
2. 提案内容写清楚：把交易手续费从 0.3% 调整到 0.25%。
3. 进入 48 小时否决窗口。
4. 如果任意 D 席位认为不合理，可以否决，提案失败。
5. 如果 48 小时内无人否决，提案通过。
6. executor / 有权限账户执行参数修改。
7. 后续交易按 0.25% 收费。

发起一次协议分红

treasury 已经把可分红资产换成 50,000 DC，团队希望分给 D 持有人。

1. treasury / dividendSource 授权分红合约使用 50,000 DC。
2. 持有 2.5 D 以上的席位钱包发起分红提案。
3. 提案写清楚：本轮分红总额 50,000 DC，资金来自 treasury。
4. 进入否决窗口。
5. 如果没有 D 席位否决，提案通过。
6. executor 调用 createRound(50,000 DC) 创建分红轮。
7. 合约记录 D 持仓快照。
8. D 持有人在前端看到可领取额度，并自行 claim。

替换核心合约模板

新的 Deal 模板完成测试和审计，需要把 Factory 的模板地址切换到新版本。

1. 持有 2.5 D 以上的席位钱包发起重大提案。
2. 提案写清楚旧模板地址、新模板地址、升级原因、审计结论。
3. 进入 120 小时 D 席位否决窗口。
4. 如果 D 席位没有否决，进入官方 DealInfoNFT 用户否决阶段。
5. 如果 NFT 否决达到有效治理 NFT 的 20%，提案失败。
6. 如果两边都没有触发否决，到期后 executor 执行模板替换。
7. 新创建的 deal 使用新模板，旧 deal 继续按旧合约逻辑运行。

修改域名广告费率

域名广告消耗速度过快或过慢，团队希望调整广告费率规则。

1. D 席位发起常规提案。
2. 提案写清楚新费率、适用范围、修改原因。
3. 进入 48 小时否决窗口。
4. 无人否决后执行参数修改。
5. 新的域名广告充值和消耗按新规则计算。
如果只是调整费率，属于常规参数。如果要迁移 DCDomainRank 合约、迁移 treasury 或更换 reporter 权限，则属于重大提案。

对外总结

D 是固定 1000 枚的协议权益代币。
持有 D 可以按比例领取协议分红。
2.5 D 以上成为治理席位。
常规参数采用席位否决制，无人反对即可执行。
重大升级除了 D 席位否决，还要接受官方 DealInfoNFT 用户否决。
分红按 D 的历史持仓快照领取，防止转让后重复领取。

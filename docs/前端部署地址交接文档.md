## 6. 前端必须更新的 ABI

本次不要只换地址，还要更新 ABI。

| ABI | 是否必须更新 | 原因 |
| --- | --- | --- |
| `DealFactory` | 是 | 新 Factory 地址、奖励事件、留言费入口 |
| `DealMessageHub` | 是 | 新增 `postMessage(deal, content)` 前端入口 |
| `Deal` / 各 Deal implementation ABI | 是 | `Completed/Canceled` 事件签名变化 |
| `DealOpenTokenToken` | 是 | OpenTT 顶替、B 清退、终局事件时间 |
| `DealReader` | 建议 | 随部署包同步 |
| `DCDomainSwap` / `DCDomainHall` | 如果重新部署则必须 | 域名入口需要指向新 Factory |
| `DealCreditGraph` | 是，如果展示信用分 | 信用分读取和事件索引 |

最重要的 ABI 变化：

```solidity
event Completed(CompletionReason reason, uint64 when);
event Canceled(uint64 when);

function postMessage(address deal, string calldata content) external returns (uint256 index);

event MessageStored(
    address indexed deal,
    address indexed sender,
    uint256 indexed index,
    uint64 timestamp
);
```

## 8. 前端调用变化

### 8.1 创建交易

仍然走：

```solidity
DealFactory.createDeal(...)
```

OpenTokenToken 仍然是在创建参数里开启：

```text
openTokenTokenFast = true
templateType = 0
joinMode = Open 或 ExactAddress
```

### 8.2 留言

旧入口不要再用：

```text
Deal.postMessage(...)
```

新入口：

```solidity
DealMessageHub.postMessage(dealAddress, content)
```

读取：

```solidity
DealMessageHub.messagesCount(dealAddress)
DealMessageHub.getMessages(dealAddress, offset, limit)
```

### 8.3 事件时间

交易时间线统一取：

```ts
const time = event.args.when ?? event.args.at ?? event.args.timestamp;
```

`Completed` 和 `Canceled` 现在也直接带 `when`，不用再查 block timestamp。

## 9. 部署方需要完成的接线

本次如果走推荐的重新部署方案，部署方需要完成：

```text
1. 部署新 DealFactory
2. 部署新 DealMessageHub(newFactory)
3. 部署新 Deal / DealNoAsset / DealAAssetNft / DealBAssetNft / DealAAssetNftOnly / DealBAssetNftOnly / DealOpenTokenToken
4. 部署新 DealImplementationRegistry，并写入 7 个 implementation
5. 部署新 DealActivityIndex(newFactory)
6. newFactory.setGlobal("dealMessageHub", newHub)
7. newFactory.setGlobal("dealImplementationRegistry", newRegistry)
8. newFactory.setGlobal("dealActivityIndex", newIndex)
9. newFactory.setGlobal("creditGraph", creditGraph)
10. newFactory.setGlobal("infoNft", dealInfoNFT)
11. newFactory.setGlobal("dlToken", DL)
12. newFactory.setGlobal("wrappedNative", WNATIVE)
13. newFactory.setRecognizedTokens(AUSD, USDT)
14. newFactory.mapExistingPair(AUSD, pairDlAusd)
15. newFactory.mapExistingPair(USDT, pairDlUsdt)
16. DL.grantRole(MINTER_ROLE, newFactory)
17. DealInfoNFT.addFactory(newFactory)
18. DealInfoNFT.setFactory(newFactory)
19. DealCreditGraph.setRecorder(newFactory, true)
20. DCDomainSwap / DCDomainHall 如继续使用，需要重新部署到 newFactory 或重新接线，并在 newFactory setAllowedCreateFor
```

## 10. 交付前检查

部署完成后，交付前检查：

1. 新 `DealFactory.dealMessageHub()` 等于新 Hub。
2. 新 `DealMessageHub.factory()` 等于新 Factory。
3. 新 `DealFactory.dealImplementationRegistry()` 等于新 Registry。
4. 新 Registry 里的 implementation 都是本次新地址。
5. 新建一笔普通 deal，成交后能索引到 `Completed(reason, when)`。
6. 新建一笔取消 deal，取消后能索引到 `Canceled(when)`。
7. 新建一笔 OpenTokenToken，B 加入、注金、投票、成交事件均有时间字段。
8. 前端用 `DealMessageHub.postMessage(deal, content)` 能写入留言。
9. 前端通过 `DealMessageHub.getMessages` 能读到留言和 `timestamp`。
10. 如果开启留言费，用户授权 `DealFactory` 后能正常发送付费留言。

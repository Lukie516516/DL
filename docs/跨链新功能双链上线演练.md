## 2. GovernanceProbe 做什么

`GovernanceProbe` 不承载真实业务资产，只保存三个值：

```solidity
address public controller;
bytes32 public marker;
uint256 public updateCount;
```

唯一业务写方法：

```solidity
recordMarker(bytes32 newMarker)
```

其作用是让 DAO 在 ETH 写入同一个标记，同时把相同 calldata 广播给 BSC。验收时比较两条链的 `marker` 和 `updateCount`，即可证明新模块治理路径完整可用。

安全边界：

- implementation 构造时永久锁定 initializer；
- proxy 只能初始化一次；
- `recordMarker` 只能由 controller 调用；
- UUPS `upgradeToAndCall` 也只能由 controller 授权；
- ETH controller 固定为现有 `DealGovernance proxy`；
- BSC controller 固定为现有 `DualBridgeExecutor`；
- 没有 controller 修改接口；
- 没有 ERC20/NFT 操作，没有普通 payable 入口，没有业务外部调用；
- 策略对写标记和升级都设置 `maxValue = 0`。

注意：标准 UUPS 的 `upgradeToAndCall` 本身是 payable，且任何地址都可能被强制转入原生币。因此不能宣称任何 EVM 合约“绝对无法持有原生币”；本模块没有提款或资产业务逻辑，DAO 策略也不允许随探针动作发送 value。

测试用 V2 只增加只读方法并返回 `version() = 2`，用于证明升级后 controller、marker、updateCount 均保持不变。V2 mock 不作为当前主网部署内容。
